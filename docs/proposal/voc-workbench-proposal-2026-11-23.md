# VOC 研究工作台专案（2026-11-23）—— Markdown 摘要版

> 本文件是专案页 `voc-yan-jiu-gong-zuo-tai-zhuan-an`（2026-11-23，11 节，状态：待评审）的 Markdown 摘要；完整原文见专案页审计文本。专案为设计提案：架构、字段与分期均为待评审方案；第三方服务能力以其官方文档为准，接入前需逐项实测。

**定位：** 一个以站外用户内容为主线的研究工作台：从论坛讨论、讨论声量与研究期刊里发现用户真实意图（P0-1 发现），用 Jev 把意图规模化打分分类（P0-2 执行），最后把发现转成一份能直接投放的调查问卷。Amazon 评价因官方 API 不开放评论文本、条款禁止抓取，只作初步来源，不押注在它身上。

**三条结论：** ① 发现与执行并列 P0，顺序不能反（Jev 在发现层只当哨兵——低置信、进不了现有清单的条目自动进发现队列）；② Amazon 降级为初步来源；③ 补上「声量、期刊、问卷回流」三块。

**三件产出物：** ① 意图注册表；② 洞察仪表盘（情感 / 问题 / 趋势 / 推荐四模块，数字按来源分开报）；③ 调查问卷（由发现直接生成题项，可导出到 Google Forms）。

## §1 定位与三条结论

工作台要解决的不是「把评价汇总一下」，而是三件按顺序发生的事：先有足够广的站外语料，再从语料里发现清单之外的意图，最后把意图变成可验证的问卷题目。

## §2 Amazon 为什么难，以及还剩哪四条窄路

官方 API 不给评论文本（PA-API 5 已弃用，继任 Creators API 只返回标题、价格、图片、平均星级与评价总数，且要求 Associates 账号近 30 天有合格销售）；条款明文禁止抓取（Conditions of Use 排除收集 listing/描述/价格与数据挖掘、机器人采集；robots.txt 对评价 RSS 等批量通道 Disallow）；反爬让数据不稳定（未登录只能看到少量精选评价，完整评价在登录墙后）。四条窄路：自有产品后台导出（合规·手工量）、公开页人工采样（合规·小样本标注）、只取聚合数（合规·只做背景）、Shulex API（初步·依赖服务方）。

替代逻辑：Amazon 评价回答的是「买过的人怎么评价这次购买」，站外论坛回答的是「人们在没被问的时候自己在聊什么、想解决什么」。发现意图恰恰需要后者——所以站外做主线不是退而求其次，是任务本身决定的。

## §3 数据源全景表

9 个来源，各标注接入方式、回答什么问题、证据等级、口径红线。证据等级：A = 可作主要依据；B = 对照与三角验证；C = 只作信号/痛点排序，不推比例。

| 来源 | 等级 | 口径红线 |
|---|---|---|
| Reddit 讨论 | A · 站外主依据 | 按 subreddit 与时间窗分开报 n；点赞数只作声量权重，不当满意度 |
| 垂直论坛与社区 | A · 站外主依据 | 抓不到的用原文片段 + 链接并注明受限；不把单帖热度当普遍程度 |
| 讨论声量 | B · 趋势信号 | 只比同口径变化；不同平台声量不相加、不画在一条线上 |
| 研究期刊与公开调查 | B · 背景与基线 | 期刊结论是人群层面证据，不直接证明本品类用户占比 |
| GitHub 开源生态 | C · 领先信号 | 只作趋势前哨；不进漏斗、不推规模与付费意愿 |
| 自有问卷回收 | A · 验证依据 | 样本来源与招募方式必须登记；小样本只报分布不报「用户占比」 |
| Amazon 评价与 Q&A | 初步 · 体验对照 | 只用 US verified 评价作产品体验依据 |
| 内部客诉（CX） | C · 只做痛点排序 | 内部数据纯负面，不推满意度与比例；原始表不外传、不喂第三方工具 |
| 用户上传 CSV | 随原始来源定级 | 来源不明的 CSV 不定级、不进统计 |

Reddit 通道正在关闭，必须按「快照」设计：RSS 已于 2026-11-13 停用（PDT v1.2 已修正措辞为「2026-11-13 起停止支持、无可用性承诺」）；未登录 .json 自 2026 年中起返回 403；公开 API 将于 2027-03 全面关闭；另有 2027-01-12 未注册应用被撤访问权的更近 deadline（见 PDT v1.2 §4.4）。采集时必须把原文、链接、日期、计数值一次性快照落本地原始层，之后任何重跑都用快照，不回源站。

## §4 对标对照表：别人怎么弄，我们借什么

两批调研合并：第一批 GitHub 开源 VOC 项目、开源研究工具与商业工作台；第二批 2026 年秋的近期开源项目与机制论文。共同结论：市面方案几乎都只做「执行」——分类、情感、汇总；做到「发现新意图」的只有机制级参考，做到「发现转问卷」的只有一个（ProductWeaver），这两块正是本专案要自建的差异点。

16 个对标（借/不借一句话，详见 `docs/benchmarks.md`）：AWS VoC Data Lake（借三段管线、插件化来源、Radar 分开算；不借整套云栈重量）；Reddit Research MCP（借 Reddit 接入层；不借作唯一站外来源）；BERTopic（借聚类引擎；簇 ≠ 意图）；ProduckAI MCP Server（借工具化形态）；Dovetail（借证据链标准）；Thematic/Chattermill（借注册表治理；不采购）；Productboard/Canny（借推荐形态；不借路线图）；ProductWeaver Plugin（借问卷三条纪律）；Waters Sentiment Engine（借四条治理规则）；Qiaomu App Review Insights（借洞察报告模板）；TopicGPT（借发现层四步流程）；Obsei（借新主题提醒；k-anonymity 不进发现层）；jordanburke reddit-mcp-server（借 Arctic Shift 档案兜底）；Consensus（借声量→投票选项）；Automated Questionnaire Pretesting（借模拟预检；不取消真人试填）；IntentGPT（借残差机制定版）。

## §5 工作台架构：六层

1. **采集层**：每个来源一个接入器，互不影响。
2. **原始层**：原文、链接、发布时间、声量数原样落盘，永不覆盖；任何一步分析都可以拿原始语料重跑。
3. **发现层（P0-1）**：BERTopic 聚类 + TopicGPT 四步双轨，互相校验；IntentGPT 机制：已知意图先用 embedding KNN / Jev 召回分掉，残差与低置信条目持续喂进候选池；人工命名/合并/拆分后进意图注册表。
4. **执行层（P0-2，Jev）**：Choice 做意图分类、Score 做满意度/挫败感/需求强度、Noul 做问题清单检测；每条保留完整概率分布；低置信进人工复核队列；放量前先用 100–200 条人工金标准测一致率与阈值，中文单独校准。
5. **仪表盘层**：情感（三个分数分开打、按意图切开）、问题检测（提及率 + 平均严重度，只在同来源同分母内算）、趋势追踪（同口径周序列）、智能推荐（每条带触发条件、证据 n 与原文、动作、验证方法四件套）。
6. **输出层**：问卷生成器（导出 Google Forms）；洞察报告；问卷回收数据回灌第 2 层，验证或推翻发现。

## §6 建议新增的 8 件东西

1. 声量基线与异常触发（每话题先攒 4 周同口径基线，陡升或新话题冒头自动触发发现层重跑）；2. 意图注册表（版本化）；3. 期刊证据层（对表，不是混编）；4. 问卷回流闭环；5. 竞品 Radar（分开算）；6. 低置信复核队列；7. 采样日志与口径登记；8. 脱敏层（作者名哈希化、去掉订单号/邮箱/地址；内部客诉默认禁止出境到任何第三方模型 API）。

## §7 统一数据表：一张表装下所有来源

字段分四组：溯源（record_id、source_type、source_url、published_at/collected_at、batch_id）、原文（raw_text、lang、rating/verified、engagement）、编码（cluster_id、intent_id + intent_probs、scores、issues）、治理（evidence_grade、review_status、author_hash）。CSV 最小字段：raw_text、source_type、published_at、source_url；评价类另加 rating、verified、产品型号。缺原文或来源的 CSV 不入库。机器可读定义见 `schemas/`。

## §8 问卷输出模块：发现怎么变成题目

映射表：新意图候选→场景多选题；意图间优先级不明→二选一迫选题/排序题；高严重度问题→经历 + 困扰度量表题；换用/放弃信号→换秤意愿题 + 触发条件多选；清单外空白→每份问卷固定 1–2 道开放题。出题红线：选项必须来自原话归纳；一道题只验证一个发现；多选题「最多选 N 项」题面写清，回收分析时剔除超选回答；人口题只放一道、非必填、放问卷末尾，不收集邮箱；发布前先过一轮模拟预检，但模拟人格不能代替真人试点，2–3 人真人试填仍是发布门槛；预估答案必须标「估计」。

## §9 分期与验收

P0 窄链跑通：统一数据表与采样日志落地；Reddit MCP 接入 3–5 个核心社区 + CSV 导入口；发现层试点产出候选意图清单 v1；Jev 执行试点（100–200 条金标准）；问卷生成器 v1。验收：拿出 ≥1 个现有清单里没有的新意图，带 n、代表原话、与现有意图的区别说明；并由它生成 ≥1 道问卷题。（PDT v1.1 后改为盲测集验收，真实研究允许"本轮未发现"。）P1 仪表盘与声量；P2 扩展与对照（竞品 Radar、Amazon 窄路常态化、GitHub 信号三角验证、feed 持续监控）。

## §10 红线

定性不推比例；Jev 概率 ≠ 准确率；内部数据不出境；Amazon 不爬；Reddit 只信快照；GitHub 只作信号；口径一致才可比；证据可点回。
