# Amazon 的四条窄路（只做补充，不做主线）

## 为什么 Amazon 难

- **官方 API 不给评论文本**：Product Advertising API（PA-API 5 已弃用，继任为 Creators API）只返回标题、价格、图片、平均星级与评价总数，不返回单条评价的标题、正文、作者与时间。Creators API 还要求 Associates 账号近 30 天有合格销售。
- **条款明文禁止抓取**：Amazon Conditions of Use 的许可明确排除「收集和使用任何产品 listing、描述或价格」以及「使用数据挖掘、机器人或类似工具」；robots.txt 对评价 RSS、会员评价页等批量通道是 Disallow。
- **反爬让数据不稳定**：未登录只能看到产品页上少量精选评价，完整评价在登录墙后；规模化访问会触发验证码、限流与封 IP。第三方「评价 API」服务本质是代爬，处在条款灰区且随时可能中断。

结论：不是技术上爬不到，是官方通道不给、条款不许、反爬让它不稳定——三条同时成立，所以只作初步来源。**工作台不建 Amazon 爬虫，不买代爬服务。**

## 四条窄路

| 窄路 | 做法 | 能拿到什么 | 定位 |
|---|---|---|---|
| 自有产品后台导出 | Seller Central / Brand Dashboard 的 Customer Reviews 里人工查看、筛选、导出自有品牌评价；或用 Vine、Request a Review 的官方回流 | 自有 ASIN 的评价原文 | 合规 · 手工量 |
| 公开页人工采样 | 浏览器人工打开公开产品页，记录页面上可见的精选评价与 Q&A，逐条留 URL 与截图 | 小样本原文 + 页面证据 | 合规 · 小样本标注 |
| 只取聚合数 | 经 Creators API 或公开页记录星级分布、评价总数、价格等聚合字段，做竞品盘子对照，不碰评论文本 | 星级 / 计数 / 价格 | 合规 · 只做背景 |
| Shulex API（第三方 VOC 服务） | 通过 Shulex 的评价分析 API 取得自有 / 竞品 ASIN 的结构化评价结果，导出后按手工 CSV 通道入统一表，批次登记来源为 Shulex | 结构化评价与标签结果 | 初步 · 依赖服务方 |

## 定位

Amazon 评价回答的是「买过的人怎么评价这次购买」，站外论坛回答的是「人们在没被问的时候自己在聊什么、想解决什么」。发现意图恰恰需要后者——所以站外做主线不是退而求其次，是任务本身决定的。

每批 Amazon 数据都要留采样登记：样本量、采样方式、ASIN、日期、verified 状态。
