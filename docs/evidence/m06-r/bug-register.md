## M04 导入与回执

### R-01 · P1 · 同文独立来源在暂存时合并

- **复现**　同一 CSV 含两条文本、隐私级别与角色相同的合成原话，来源 URL 和外部 ID 分别不同。旧规则将第二条标为重复，M05 只收到第一条候选。用旧暂存规则构造的历史批次中，第二条详情返回 404。
- **修复**　按规范化来源保留同文独立行。同一规范来源、同来源类型的外部 ID 冲突、来源位置不足等情形继续执行原有去重规则。只有暂存候选发生变化时使用新版确认指纹。历史令牌重放原批次，重新质检可确认新版批次。同源旧记录撤销后，新批次对应同源行继续受限，独立来源按自身许可复核。
- **证据**　Windows 11 专项 7/7，耗时 3.115 秒，退出码 0。`test_same_sheet_preserves_distinct_sources_for_m05_review` 核对两条独立行各自进入 M05、独立审核及撤销，以及同源等三个去重反例。`test_legacy_same_sheet_batch_can_be_rechecked_without_changing_old_receipt` 核对两版令牌独立回放、重核及来源撤销。[用例](../../../tests/test_pre_m06_audit.py)

### R-02 · P2 · 同一文件的多份撤销批次可返回旧回执

- **复现**　同一文件、映射和隐私设置产生旧版、新版暂存批次。两份批次都撤销，且都没有逐行审核。预览命中已撤销批次时，旧选择缺少显式顺序，可能返回旧批次令牌。
- **修复**　遮蔽预览按创建时间及行序选择最新回执。确认令牌仍绑定原批次，撤销状态和空样本保留。
- **证据**　上述 Windows 11 专项中的 `test_revoked_previews_prefer_latest_governed_staging_receipt` 用新旧令牌分别检查撤销重放，并核对预览返回新版令牌、撤销状态及空样本。[用例](../../../tests/test_pre_m06_audit.py)

## C4 关系版本授权

### R-03 · P1 · 关系只读投影可暴露授权范围外的片段版本

- **复现**　在双片段版本合成夹具中，读权限只涵盖第一版的一组精确证据。项目需求发生投影和产品意图投影此前按项目准入后解出指定版本或当前封版，返回的投影可能带有读权限范围之外的版本元数据。
- **修复**　在读取已解析 `segment_revision` 的投影前复核该版本的读授权，保留原有精确证据与当前资格复核。C4 关系投影和 C5 分母查询复用这一判断。
- **证据**　Windows 11 的 C4/C5 定向复测 25/25，耗时 18.924 秒。`test_project_relationship_views_require_read_access_to_the_resolved_revision` 检查工程和正式模式、两个投影入口、获准的第一版以及拒绝当前头、未获准版和未知版。[用例](../../../tests/test_m06_relations.py)

### R-04 · P1 · 关系命令的版本冲突可能透露未获准版本

- **复现**　在同一双版本夹具中，操作者具备关系命令权限，读授权只涵盖第一版。预检、工程归因与发布在核对版本时可能暴露未获准的请求版本，或通过冲突响应透露已获准旧版之后另有当前封版。
- **修复**　在同一事务内先校验请求版本的读权限。命令需对比当前封版时也先复核当前封版的读权限。隐藏版与未知版走同一拒绝路径，双方均可见且不一致时保留版本冲突语义。
- **证据**　同一 Windows 11 定向复测中的 `test_commands_do_not_disclose_a_revision_outside_the_read_grant` 覆盖预检、工程归因和发布的拒绝分支，比较操作前后的数据库状态，并验证获准当前版可进入预检。[用例](../../../tests/test_m06_relations.py)

## 关系与统计界面

### R-05 · P2 · 撤回所选项目授权后界面仍保留旧项目状态

- **复现**　选择项目甲后，授权列表改为只有项目乙。旧界面保留甲的内部选中状态，并显示暂无获准项目，尽管乙仍可选择。
- **修复**　重新查询时清除失权项目及其片段、冻结范围和旧结果。授权列表仍含项目时提示选择获准项目。新选择按新项目重新取数。
- **证据**　Windows 11 上的 Chromium 159.0.8154.6 对照确认旧版出现错误提示，修复版显示选择可访问项目的提示。仓库用例覆盖连续刷新、片段及冻结范围清空、显式选择乙后不展示甲的标识或原话。固定源码归档的 Chromium 全流程退出码为 0，生成 26 张合成截图。[用例](../../../tests/relations_browser.py)

## C5 分母规模性能

### R-06 · P2 · 批量资格查询反复扫描同批次记录

- **复现**　实际 SQLite 查询计划以 500 个绑定键执行旧 `IN` 路径。计划先取项目批次，再按批次行索引前缀扫描，每组键均可能重复扫描同一批次。
- **修复**　用固定 SQL 的 `json_each` 提供有界请求键集，以 `CROSS JOIN` 驱动 `import_rows(record_id)` 唯一索引逐键查找。在原事务中继续应用当前审核、许可、撤回、保留期及同文件副本规则。
- **证据**　已核对旧扫描和候选唯一索引查找的查询计划。三档完整响应等价，并发撤销及独立恢复复核通过。十万条批量热读样本 P95 从 62.968 秒降至 39.073 秒，十五秒目标仍待后续优化。[规模复测](performance-comparison.md)
