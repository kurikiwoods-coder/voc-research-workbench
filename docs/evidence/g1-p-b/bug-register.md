# G-1-P-B 独立复审缺陷

复审使用隔离 SQLite、合成条目和受控传输。编号对应本轮尚未发布的实现候选。正式研究及供应商探针均为 0。

| 编号 | 级别 | 实际发现 | 修复和复测 |
|---|---|---|---|
| PB-01 | P0 | 初版请求体前置检查遍历扁平路由，未覆盖 FastAPI 的嵌套路由。隔离测试中未授权导入曾返回 201，部分语料查询进入业务执行 | 使用 `EditionRoute` 精确处理请求并保留全局兜底。复测嵌套路由、未知项目和格式错误的合成请求体均在权限边界内拒绝。已关闭 |
| PB-02 | P1 | 在一个项目上传时，全局清理曾删除另一项目的过期草稿，全局上限也会影响无权查看的项目 | 个人版按项目和冻结范围清理及计数。复测八份外部草稿和一份过期草稿不改变当前项目的导入，用途和数量保持隔离。已关闭 |
| PB-03 | P1 | 仅持有导入权限的 Owner 能在批次详情读取已核验原话及元数据。审核回执也须适用独立语料读取权限 | 导入视图单独校验读取权，审核要求同时具备读取权。复测导入批次保留状态，受限原话和字段遮蔽。已关闭 |
| PB-04 | P1 | 无必要操作权限时，真实与未知对象可能得到不同状态 | 权限检查先于对象查询。获得操作权后再核对象的项目和冻结范围。无权请求的存在性复测结果一致。已关闭 |
| PB-05 | P1 | 路由预检通过后，项目状态可在实际读取前变化 | 在保护数据的当前读事务内重新核对授权。原话详情、资格、导入回读和报告均实测拒绝失效结果。已关闭 |
| PB-06 | P1 | CLOUD 下旧归档 CLI 对未知批次会创建商用数据库，直接恢复路径也缺模式复核 | 归档与恢复在打开库及传输前限制版本和部署；历史归档脱机核对继续通过。已关闭 |
| PB-07 | P2 | 新状态投影曾允许用当前供应商审查配对较早的 G-1 状态行 | 验证同一已结束尝试的商用六项状态、已登记门禁证据和当前同一审查。原 G-1 历史验收保留。已关闭 |
| PB-08 | P3 | 未认证直接访问个人正式分母状态 API，原关系响应包装会省略浏览器身份验证挑战 | 先从「版本与研究准入」打开「核对已授权项目」完成 Owner 验证。接口仍然拒绝无权读取。记录为本机体验债务 |

新增未关闭 P0/P1/P2/P3 为 **0/0/0/1**。Windows 11 本机 ACL、登录和 DPAPI 另列实机验证。
