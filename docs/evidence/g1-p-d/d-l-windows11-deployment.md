## 独立正式验收工作区

- 负责人授权在当前可信 Windows 用户的 LocalApplicationData 下创建全新目录。主工作库、外部授权档案、一致性备份和恢复目录独立。仅核验新建工作区，历史库和公司资料均未打开。
- 主工作库新建至 Personal v11。以独立的冻结研究范围和本机 Owner 权限完成 `provision`。Owner 证明由 CurrentUser DPAPI 保护，本机验证配置和受保护部署锚绑定当前工作库文件身份。供应商凭证绑定为 0。
- 用仓库既有 SQLite Backup API 校验逻辑生成一致性 v11 快照，在独立新目录恢复。主库、快照、恢复库均为 v11，`integrity_check = ok`，`foreign_key_check` 无违规，冻结项目与范围 ID 一致。恢复库重读成功，原库的正式执行部署锚在恢复库被拒绝。
- 三次独立回环启动均通过，覆盖主库首次、主库重启及恢复库启动。首页、健康检查、版本及 Owner 项目回读通过，每次服务停止后释放端口。主库重启后 DPAPI 和部署锚回读一致。
- 初次部署验权发现部分新建子项带 Windows 默认系统和管理员 DACL。随后仅对新建目录内的项目收敛访问规则。最终该目录及 18 个下属项归当前用户所有，DACL 允许条目仅该用户，部署复验退出 0。首轮端口检查发生在 Windows 服务子进程退出完成前，改用正常停机并复验后通过。
- 正式批次、外发授权、真实请求、供应商探针、余额查询、Token、费用和分母增量均为 0。实际目录、身份标识、授权包和数据库留在本机。恢复演练覆盖此次新部署的空账本，正式批次仍需独立可信的恢复连续性复核。
