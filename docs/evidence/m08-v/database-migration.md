# M08-V SQLite v7 → v8 迁移及恢复

原生 Windows 11 普通登录用户，Python 3.12.9 / SQLite 3.45.3。v7 合成库由 M06-R 归档源码 `9c27231376fcc32aae39a9b63df6fa9b9b98c4c6` 生成。v8 迁移使用本轮源码 `74590d4a4d43a66c7a3296943da9205bc6ff65e0` 的 Store。专项在隔离库和隔离备份中执行，Python 外部连接尝试为 0。

- v7 输入有 3 条已导入审核的合成原话、3 条 M06 发生与证据关联、冻结项目范围及多版注册表。使用现有 SQLite 一致性备份捕获 32,992 字节活动 WAL。备份保留 4.0.0 注册表头和 64 行，后续源库保留 5.0.0 注册表头和 66 行。
- 源库和备份恢复库分别升级至 v8。逐项比较 194 个历史 schema 对象和 35 张历史表全部数据，其中 25 表有数据。合成项目、原话、关系、历史版本及稳定 ID 与各自迁移前一致。同库再次打开及两个线程竞争打开恢复库均通过。
- 故障一为迁移脚本在写事务内遇到 SQL 错误。故障二为 Windows 子进程在 COMMIT 前被终止，观测退出码 1。两者均保留完整 v7，未残留部分新增表或版本变化，重试后均升级到 v8 并再次通过数据等值校验。
- M07 草稿命令在重开和备份恢复后按同键重放，仍为 1 份草稿、1 份修订、1 条命令记录。M08 任务回执重放通过。工作库与每任务工作库为 v8，M01 合成契约库、M01/M02 诊断库、M08-A/B 演示账本、M08-C/D 任务账本和 PackyCode 合成预检账本沿用隔离 v1。前五类实库完成独立一致性备份及恢复比较，任务工作库、预检账本另由既有任务及预检回归覆盖。
- 实测 `PRAGMA integrity_check = ok`，`PRAGMA foreign_key_check` 返回零行。空库 v8 启动 3/3，三个路径各同库重启一次。独立迁移探针和 32 项定向回归退出码均为 0。
