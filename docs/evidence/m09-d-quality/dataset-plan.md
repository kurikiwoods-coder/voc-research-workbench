# M09-D 质量实验数据集与留出验证

四个数据批次均为人工构造的中英语料。样本是虚构的短篇产品反馈，文本、语言和稳定 ID 固定。每个批次内打乱文本顺序后分配 ID。数据设计时隔离旧盲测内容和模型输出，固定 v1 文件后按 SHA-256 核对。标签和语言配额由同一名编制者制定，最终核验可由独立评分者复算。数据仅反映中英短文本的受控表现。

## 意图和标注规则

开发批含三类产品。扫地机的意图分别是保留多层地图及遵守禁区，耳麦的意图分别是清晰向对端传话及降低佩戴者听到的环境噪声，显示器的意图是保持用户选定的输入源。验证批采用不同产品。文档扫描区分完整采集正反面与跳过真正空白的页面，灶具区分烹饪中锁定操作与防止关机时误启动。

以原句明确表达的操作目标为标签依据。背景、现状、让步及否定用于消歧，尤其关注谁听见声音、设备处于何种状态、保留何种结果。同类表达覆盖请求、抱怨、含让步的描述及实际使用约束。多意图同等明确、上下文不足以归类、或意图仅出现一次且缺乏可重复证据的行统一标为 `null`。评价仍逐行计入这些证据。给残余行分配聚类会计入残余误分。

中英语句在同一意图中独立写作，采用不同物品、场景和句式。两语配额固定，语言仅用于输入语言标记与结果分组。数据刻意包含容易因设备名、背景词或正反近义表达被混并的意图。自然语料中的长尾占比、方言、混合语言、跨渠道差异与多意图标注一致性尚待实证。

输入结构为 `{version, rows: [{id, text, language}]}`，其中 `language` 为 `en` 或 `zh`。独立标签文件结构为 `{version, labels: {id: intent_or_null}}`。同一批次的版本和 ID 集合必须吻合。

## 最终留出验证

1. 在最终运行前锁定基线和至多一个拟验证方案。登记代码提交、模型资产哈希、文本预处理、配置、随机种子，以及评分与接受条件。[实验预注册](experiment-plan.md)
2. 在隔离本机、固定模型与离线运行时，用两份留出输入分别计算。聚类进程仅接收输入、冻结参数与模型。保存 ID 对应的原始分配、后处理结果、候选映射、耗时与输出摘要，然后交给独立评分。
3. 评分方验证冻结的输入和输出及两份本机标签的摘要，再按固定协议一次评分。结果给出匹配后的逐意图纯度和召回、覆盖、拒判、无支持候选、候选与分配稳定性以及负例切片。负例切片的有效结果允许零候选。如果出现候选，逐个核对其证据。
4. 同一数据版本保留全部失败行与原始分配。若冻结条件未达成或结果不确定，保留原生产基线。分析后若需再次选参，创建另一个尚未评分的留出版本。把任何后续真实验证单独交给 G3 审核。

两份留出标签作为本机独立文件保存，交付记录只登记标签摘要。编制者已知道标签，编制后未参与方案选参。本轮留出批次未用于推理、评分或选型。此处的隔离用于降低研发反馈污染，未采用访问控制或加密封存。
