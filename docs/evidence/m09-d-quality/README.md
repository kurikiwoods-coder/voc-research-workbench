## 建议与接续

现有结果未提供满足覆盖和召回护栏的挑战者。建议维持当前生产表现及审核状态，并先验证表示层能否区分同一产品中不同的动作、对象和触发条件。采用同产品硬负例与跨语言同意图对，测试固定 MiniLM、锁定的 Multilingual E5 Small 和保留上下文的输入表示。先测配对排序、近邻纯度、CPU 成本与差错分层。通过后，再评估候选簇局部拆分和高冲突残余的人工复核。候选继续保留原证据及所属运行，关键词和代表片段按最终成员重算。独立证据数按获准去重组统计。后续接入须复验 M09-C 重放、撤销和精确来源链。

新留出输入共 44 条，标签独立保管，当前留出推理和评分均待执行。单一方案及依赖冻结后交负责人审阅。若开发与验证仍无满足护栏的方案，则保留留出批供后续改进使用。结果只覆盖受控中英短文本，真实长尾、多意图片段、跨渠道、更多语言和人工一致性均待验证。M09 继续 PARTIAL，G3 与 P0-1 待验收。[留出预注册](experiment-plan.md) · [数据保管与摘要](dataset-plan.md)

## 复跑

在隔离 Windows 工作区使用已经锁定的 M09 CPU Python、MiniLM 目录与应用 Python 包目录。取新的输出路径，运行下面两条后将 `dev` 换为 `validation` 重跑。

```powershell
& $m09Python docs/evidence/m09-d-quality/experiment.py fit dev $devPredictions --model $m09ModelDir --app-site-packages $appSitePackages
& $m09Python docs/evidence/m09-d-quality/experiment.py score dev $devMetrics --predictions $devPredictions
```

同一套评分也支持经冻结的留出方案。两条命令都要明确 `--challenger` 并分别指定 `holdout-mixed`、`holdout-negative`。保存拟合结果后，评分方按数据计划核对本机标签摘要，再通过 `--gold` 指定标签文件。JSON 输入、标签和预测摘要统一用 LF 内容计算。
