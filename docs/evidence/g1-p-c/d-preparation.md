# G-1-P-D 最小实证准备

本文件记录 C 阶段制定的 D 取证规范。D 准备及离线复验已完成，真实执行 `BLOCKED`，请求和新增外部费用均为 0。个人门禁保持 `NOT_EVALUATED`，商用 G-1 保持 `BLOCKED`。C 的供应商审批是 D 的前置。D 还需要具备批次隔离、发送前核验和账本的个人预准入入口。现有商用 `run_checks` 和 `discover` 只用于原版本路径。[D 最新复核](../g1-p-d/README.md) · [个人门禁](../../architecture/personal-research-gate.md) · [预准入契约](../../architecture/g1-personal-gate-contract.md) · [商用检查](../../../src/execution/checks.py) · [来源发现](../../../src/ingestion/public_source.py)

## 最低请求数

首次从头取证的顺利路径共 **4 次外部请求**，包括两次模型调用、一次搜索和一次回源。使用同一条经核验、获准外发的真实公开原话，冻结题组及最终脱敏载荷。一次搜索取得合格候选链接，并在第一次回源时核实原话和许可。两次模型响应均须成功。候选不合格、分片失败或预算不明时暂停并记录缺项。

| 检查 | 新请求 | 同批必留证据 |
|---|---:|---|
| C0-3 搜索发现 | 1 | 选择一个已获准的 Tavily 或 Brave 账户。保存查询、时间、命中 URL 和回执摘要。 |
| C0-3 来源回源 | 1 | 打开同一命中的许可页面或官方接口。保存至少一条真实用户原话、原址、回源方式、时间、许可、用途、必要署名和摘要。 |
| C0-1、C0-2、C0-4 模型与计量 | 2 | 同一个获准账户及精确通道调用 `jev-1.14.0`，11 题自动按 8+3 发送，按题号合并。保存每片真响应模型、每道 Choice 选项概率、每档 Score 概率、独立 Noul 概率及档位和题号，以及两片实报用量与账本关联。字段缺失登记 `schema_gap`。 |
| C0-4 持久化与恢复 | 0 | 在本机核预算预约、SQLite 写入和重启回读、同键恢复与重复计费防护。分别保存实报用量、费用、估算、余额状态。余额可明确记为未同步。 |
| C0-5 内部隔离及故障 | 0 | 在隔离库用合成标识和故障夹具验证出站前拦截、断网、凭证无效、额度不足、契约错误、限流、上游故障。保存本地审计和零外发证据。 |
| C0-6 三层关系与全局召回 | 0 | 在隔离库核验 2 个产品品类、3 个任务大类、至少 30 个意图，记录固定注册表、索引、关系与跨品类候选。全局召回 Top-K 加 None 上限为 20。 |

新批次可逐项纳入仍有效的历史 C0-3 搜索和回源证据。登记原批次、用途、来源、摘要、有效期及复核人，并核对同一命中链路、当前许可及回查路径。两项都纳入时最低 **2 次**新请求。仅一项纳入且新旧证据能组成同一合格链路时最低 **3 次**。原 PackyCode 合成 8+3 回执与费用只用于历史旁证。两次真实模型请求仍按新批次核定。[历史 C0-3 证据](../p0-0/tavily-live/README.md) · [模型分片实现](../../../src/execution/jev.py) · [历史合成费用](../g1-rb-f/README.md)

## 执行前确认

- 由可信 Owner 冻结个人版验收项目、具体范围版本、用途、UTC 窗口、题组及证据摘要。核对操作者和审批者身份、规则版本、授权依据、到期及撤销条件。保留独立的验收批次及审计域，正式编码、发布回执和业务分母继续关闭。
- 对实际供应商、服务条款、账户 API 权利、通道、上游、固定模型及当前凭证版本取得有效 C 审批。逐项核对账户/API 使用权、供应商条款、来源权利、数据保护、预算控制、项目授权。按实际条款、数据和用途判断哪些风险必须拿到证据。符合政策的非强制未知项须有理由、影响、保护措施、责任人和复核期限。[个人审批政策](../../architecture/personal-approval-workflow.md)
- 留存已批准搜索账户、查询范围和来源白名单。按 M05 核对逐源采集、保存、转换、分析及外发权限，保留用途、许可时效、留存及删除义务。逐次核对最终脱敏输入和摘要。内部 CX、企业私密资料、问卷原始答卷及未经授权的敏感个人信息禁止外发。原始材料、凭证、完整账单和运行库留在获准本机。
- 在上述材料齐备后，由负责人另行签发仅限该批次的 D 执行授权，绑定实际账户、通道、固定模型、凭证版本、输入及证据摘要、期限和请求上限。发送前复核当前授权、来源及预算，逐片预留。响应后保存真实回执并复核提交资格。六项都完成后提交 G-1-P-R 独立复审。

## 预算与停机条件

申请按已纳入的证据确定本批请求上限。全新取证上限按 1 次选定搜索、1 次获准回源、2 次模型发送申请。实际账户的搜索额度单位及一次搜索的预计消耗、两片的输入和适用输出上限、总 Token 上限、现行计价与币种、每项和批次费用上限，均由负责人在 D 授权中填入并复核。模型限额根据审核通过的两片最终载荷、可控响应上限及实际账户可执行的约束计算。当前金额及 Token 上限待该批核定。

请求前预约。达到调用、Token、费用或账户额度上限，以及遇到许可、资格、凭证或授权变化时停止。回执或扣费不明时保留原预约和请求键，先与供应商对账。已保存回执的复核、SQLite 重放和演练在本机离线完成。需另发请求、补查外部余额或调整额度时，由负责人追加批准后计入授权上限。记录搜索实际扣额、两片实际用量和可核账单，保留估算及明确的未同步状态。[实施计划](../../planning/g1-personal-implementation-plan.md#测试和后续出场) · [原验收矩阵](../../requirements-matrix.md#可机读的需求映射)
