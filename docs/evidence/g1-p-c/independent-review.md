# G-1-P-C 独立安全复审

独立复审人员在实现人员之外进行只读检查。开发方负责修复和回归。检查范围包括 Personal Local 权限、审批当前资格、追加事件、证据、SQLite 迁移、凭证生命周期、个人商用隔离和真实外发门禁。复审期间没有调用真实供应商或研究 API。

| 级别 | 发现 | 实施处置 |
| --- | --- | --- |
| P1 | 单一密文替换早于 SQLite 提交，失败事务可能使既有凭证不可用 | 密文按范围和版本分开存储，SQLite 事务提交后切换当前锚，失败继续读取原版本 |
| P1 | 撤销依赖打开当前凭证库 | 撤销按当前授权和精确事件追加，凭证或登记簿不可读仍可撤销 |
| P1 | 证据恢复后两条审批可能同时有效 | 同身份的既有批准须显式撤销，才可批准替代事件 |
| P1 | 请求者选择材料可能遗漏适用的强制风险 | 服务端扫描适用的权威登记，强制条件独立于所选证据 |
| P1 | 全局凭证可被不同项目读取或轮换 | 文件、DPAPI 绑定和 SQLite 当前锚均落实到项目与冻结范围 |
| P2 | 权限重签后的引用可能重复 | 事件增加当前授权窗口及权限集版本绑定，同时检查操作者 |
| P2 | 证据可被历史追加或以链接指向其他文件 | 封存快照成员数，拒绝链接和非普通文件 |

独立复审在固定源码 `0b25c0a375ffa6660884287bc4e2b0c25c535a65` 逐项复核了上述处置，未发现残留 P0/P1。核对了权限重签、同范围下撤销后再批准、按当前范围封存证据、凭证事务失败时的旧版本有效性，以及 C 路由无供应商发送能力。运行回归结果见[验收记录](README.md)。

复审保留一项 P2。若 SQLite 已提交凭证变更，随后清理未绑定密文时出现文件系统错误，接口可能返回 503。调用方应重新读取当前绑定状态。未绑定文件仍使用 DPAPI 加密，并且不参与当前凭证读取。后续应区分已提交与清理待办。[缺陷登记](bug-register.md)
