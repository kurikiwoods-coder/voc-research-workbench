# 研究项目与范围

工作台运行后打开「研究项目」。首次出现 API 配置向导时，可以选择「稍后配置」。研究项目保存在工作台主 SQLite 中，可以离线创建和维护。

## 从项目开始

1. 点「新建项目」，填写项目名称与核心研究问题，再按研究需要补充研究对象、目标及背景。
2. 选择研究模式、市场、语言和时间范围。研究对象可以是产品、服务、用户群体或跨品类需求。
3. 保存后可以在项目列表搜索、按状态筛选和排序。点项目名打开详情，点「设为当前」切换本机工作空间选中的项目。
4. 项目状态可设为「草稿」或「研究中」。归档前会确认，归档将保留版本和关联记录，并在需要时清除当前选择。筛选「已归档」可找到项目并恢复归档前的状态。

| 研究模式 | 引用规则 |
|---|---|
| 单一产品研究 | 一个产品 ID，可选一个品类 ID。 |
| 单一品类研究 | 一个品类 ID，范围覆盖该品类中的产品或服务。 |
| 多产品、多品类研究 | 至少两个产品 ID 或至少两个品类 ID。 |
| 跨品类用户需求研究 | 至少两个品类 ID，使用同一个核心研究问题连接品类。 |
| 开放式研究 | 以研究问题限定范围，两个引用列表留空。 |

每行填写一个已知的产品或品类 ID。M03 仅保存引用，品类注册表的状态与有效性核验将在 M06 接入。范围标签与原话证据的品类归属单独管理。用户任务、目标群体、数据来源偏好及纳入和排除标准一起保存。填写来源偏好后，站点许可与来源审核仍按 PDT 执行。

## 保存与冻结范围

改动研究问题、范围时间、引用、用户群体或其他范围字段后，系统生成新的范围版本。仅修改项目资料会保留当前范围版本。「范围版本历史」可查看每个版本创建时间、变更字段、变更说明及完整快照。冻结当前范围后，继续修改将生成新的待冻结版本，旧冻结版本仍可引用。

项目标识为 `study_id`。每份范围快照都有稳定的 `scope_id` 和项目内的 `scope_version`（如 `v2`）。后续导入、采集与分析批次应持久化成对的 `study_id`、`scope_id`，并记录该范围的 `scope_version` 用于溯源。写入需要冻结范围的批次时，应以复合外键引用 `study_scope_freezes(study_id, scope_id)`。历史读取使用原版本，当前项目选择只用于启动新工作。

## 本地接口

| 方法与路径 | 用途 |
|---|---|
| GET /api/studies | 未归档项目列表及工作空间当前项目。 |
| POST /api/studies/search | 用 JSON 的 `query`、`status` 和 `sort` 查询，研究词无需出现在 URL。 |
| POST /api/studies | 创建项目及 v1，以 `request_key` UUID 防止相同提交重复入库。 |
| GET /api/studies/{study_id} | 项目资料、当前范围和版本索引。 |
| PUT /api/studies/{study_id} | 提交完整编辑表单及读取时的 `revision`，陈旧表单返回 HTTP 409。 |
| DELETE /api/studies/{study_id}?revision=N | 可恢复归档，保留项目和所有版本。 |
| POST /api/studies/{study_id}/restore | 用读取时的 `revision` 恢复项目。 |
| POST /api/studies/{study_id}/select | 设置工作空间当前项目。 |
| GET /api/studies/{study_id}/scopes | 查询范围版本索引。 |
| GET /api/studies/{study_id}/scopes/{scope_id} | 查看项目所属的完整 StudyScope 快照。 |
| POST /api/studies/{study_id}/scopes/{scope_id}/freeze | 冻结当前版本。 |

组件复用本机 FastAPI 同源保护。直接调用变更或查询表单时，请从回环地址发出请求，并附上与服务地址相同的 `Origin` 和 `X-VOC-Action: connectivity`。接口不调用外部供应商。现有主库随启动从 v1 升级至 v2，既有运行、证据、结果和额度保留。凭证诊断和合成契约库仍使用原有独立存储。
