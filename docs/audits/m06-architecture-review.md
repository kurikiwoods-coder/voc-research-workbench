## 五项审核意见

| 方向 | 可保留的设计 | 需落实的修订及边界 |
|---|---|---|
| A 数据库与事务 | SQLite、不可变发行、项目复合键、显式版本及幂等命令适合 P0。 | 外键父键需完全匹配；根记录、可空复合键、引用所在项目和版次均要独立检查。部分索引只能限制最多一个主类；无主、跨版或停用主类必须在发行入口拒绝。发行、引用、版本竞争和回执写入同一事务。见[实体和约束](../architecture/m06-data-model.md)。 |
| B 研究方法 | record_id 定位来源行，evidence_id 固定原文区间，mention_id 固定项目内的一次独立需求表达。 | 同词、近义、同一次发生、同一人、同一意图分别建模。同次转载需可核原事件与区间或显式出处链；原创和转发附言分别切片。弱线索交人审；报告待核率的分层差异。旧版稳定引用经重切沿替代边追到后继。[方法裁定](../architecture/m06-design.md) |
| C 统计 | 同证据的范围、来源、产品、窗口先一起筛，再按 mention 去重，主类独占计数。 | 只取当前决定；失格上下文使该决定失效，幸存证据可继续支持发生。当前完整负判断、无编码、失败及无主分别处理。排除按候选输入并单列未切片整行。正式未准入返回 unavailable 和 null。[统计契约](../architecture/m06-statistics-contract.md) |
| D 许可与隔离 | M05 为工程资格唯一事实源。 | 同连接写内复核、最终 UTC 复核及读/导出时再查各承担不同责任。共享定义使用允许字段投影；代表原话不足须由有权审核者判定，项目视图隐藏证据不等于全局失格。已外发件按分发登记处置。[API 契约](../architecture/m06-api-contract.md) |
| E 下游、性能与维护 | 继续沿用六层架构与本机 SQLite。 | 在 1k/10k/100k 合成夹具上实测索引、同证据过滤、键集分页、复制版本及 WAL 一致性备份；完整成员版应按一批确认发行。10 万行复制一版主库增 9,216,000 B，持写锁约 487 ms；性能数据仅覆盖简化查询。[规模记录](../evidence/m06-b/scale-results.md) |

**数据库建议。** 在 v6 副本验证父键唯一性，按项目/版本固定键、发布门和当前决定分别建约束。提交前在同一连接、同一写事务上重用当前 M05 判定，公开 Python 方法与 HTTP GET 保持兼容；锁外准备候选，锁内按预期版本和 UTC 时点复核后短事务发行。读取报告绑定内容版本并重核当前许可。备份采用 SQLite 一致性备份并实际恢复校验。逐表约束、幂等及回滚的复验条件见[数据模型](../architecture/m06-data-model.md)与[实验索引](../evidence/m06-b/README.md)。

**产品生效建议。** P0 保留逐边人工生效，可用来源明确的结构化规则自动提议；SKU、scope 或搜索词不足以证明原话所指对象。经验证的限定规则自动生效与 AI 自动判定等负责人另批。方案对准确性、人力、自动化、误判、扩展、校准与责任的比较见[方案 A/B/C](../architecture/m06-decisions.md)。

**分母复核。** 在相同切片，10 个已知抽取输入中有 1 个重复、1 个撤销、1 个出处不可核。7 个独立合格发生按 published_classified、none_unknown、review_pending、partial_or_schema_gap、pending_parent、other_pending 顺序为 2、1、1、1、1、1；两个主类各计 1。只有同一已知输入台账能这样对账。URL、页面、抽取输入及唯一发生之间不得直接相减。含同一发生的两个产品小计须重算并集。另一夹具中来源 A 只支持秤，来源 B 只支持炸锅，同时筛 A 和炸锅应为 0。原 24 例逐条保留判断及修订依据；新增 16 例各给输入、状态、计数、错误模式和可执行测试步骤。[逐例记录](../evidence/m06-b/counterexamples.md)
