## 目的

用站外真实用户原话发现清单外的新意图，用 Jev（强制，`jev-1.14.0`）规模化编码，
再把发现变成能投放的验证问卷，闭环回流。Amazon 只作初步来源，主线是论坛、
讨论声量与期刊。

工作台是全品类的，不是营养秤专用的。COSORI 营养秤只是第一个跑通的试点品类。

## v1.2.1 → v1.3 改动

### 1. 新增第 6 章「大类体系与双向索引（全品类）」

- 大类注册表：每个大类一条记录，带名称、定义、包含 / 排除标准、来源（预设或发现）、
  版本与状态；只升版本、永不静默改写，与意图注册表同一治理方式。
- 意图—大类关系硬规则：`category_ids` 可多个，`primary_category_id` 有且唯一，
  且必须在 `category_ids` 内；关系只存注册表一处，不在 Jev 问题或问卷里另起一套。
- 双向查找规格（四个方向）：意图 → 大类（搜意图返回所属大类，主大类排第一）、
  大类 → 意图（搜大类返回其下意图）、全局搜索、程序接口。两个方向都是正式入口，
  都能下钻到原文与批次。
- 大类发现流程：残差信号 → 候选起草 → 覆盖 / 区分度验证 → 人工确认；
  允许“本轮未发现新大类”，塞不进现有大类的候选意图走“新大类候选”，禁止硬塞。
- 计数口径：汇总、合计、趋势一律只按主大类算，次大类只在下钻时展示，
  不得相加、不得重复计数；附对账校验。
- 跨品类迁移：一个意图挂多个大类时，在不同大类的问卷里可以重复出现，
  回收分析时按意图归一，不重复计数。
- 验收新增 CAT-1～CAT-6。因新增一章，原第 6–14 章顺延为第 7–15 章，
  全文交叉引用已同步。
