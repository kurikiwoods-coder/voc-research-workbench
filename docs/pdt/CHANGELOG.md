## v1.2 → v1.2.1（2026-11-23，Ryan 自写，待评审）

技术连通性、Jev API 契约与复现性修订版，不改产品定位、六层架构、全网搜索方向或 Jev 强制执行原则。

| 变更点 | v1.2 存在的风险 | v1.2.1 的可验收修复 |
|---|---|---|
| Jev 1.14 版本锁定 | 直接写死 1.14，未要求实测服务商是否接受该固定 ID | 先 P0-0 发真实请求，核对请求与返回 model_id；禁别名静默回退，版本不匹配即阻断放量 |
| 8 题与选项上限 | 超过 8 个 Choice/Score/Noul 判断会报错 | 每个请求 ≤8 题；Choice 选项按 jevmodel.org ≤20；分组、幂等重试、结果合并和总 Token 入账 |
| Score 返回契约 | 原 PDT 强制各档概率，但第三方响应示例只有 score/confidence | 先实测 Score.probabilities 是否存在；缺失不伪造，切官方接口或将该服务商标记不符合完整编码验收 |
| 隐私和留存 | §6.5、§8.2、§13.2 与 CX 绝对禁令不完全一致；ZDR 资料陈旧 | CX 仅本地/人工，不得提交任何外部模型；TypeSafe ZDR 免费但须主动开启，第三方另行审查 |
| 发现层复现 | 要求两次运行逐字完全一致，不符合 LLM/聚类实际 | 保存快照、版本、种子、参数、输出；回放可重现已保存结果，重算报告稳定性差异 |
| 验收顺序 | P0 直接开始大模块开发，接口风险后置 | 增加 P0-0，真实 API+网页原话+数据库+额度回填通过后方进入 P0 |

验收新增 J-11（分片与幂等成功）、J-12（Score 契约核验）、J-13（P0-0 连通性与隐私门），§12.1 交叉引用同步为 J-1~J-13；新增 G-1（P0-0 连通性）与 §12.0 C0-1~C0-5 五项真实/合成测试。已核实：jevmodel.org 每请求最多 8 题、Choice 2–20、Score 2–10（文档 2026-11-18 更新）；TypeSafe 官方 Score 返回 score、probabilities、confidence；TypeSafe ZDR 对每个组织免费但须主动开启。

## v1.1 → v1.2（2026-11-23，待评审）

v1.2 不改 v1.1 的来源主线、六层架构与 Token Center 设计，只补三类内容：Jev 三条硬规则写死（版本锁定、Box 排除、None + Noul 守门）、Reddit 两处时间线措辞、两处列表编号修复；另新增附录 F（GitHub 仓库设计）。

| 变更点 | v1.1 | v1.2 |
|---|---|---|
| Jev 模型版本 | 全文未写版本号，阈值随别名漂移的风险未锁 | 锁定 jev-1.14.0，禁用 jev-latest；换版本必须重跑金标准并重定阈值（§6.1、J-9） |
| Jev Box 类型 | 未提及 | 明确排除出 P0：Box 是图片框选，文本 VOC 不用（§6.1） |
| Choice 兜底 | 示例里有「其他」，未成硬规则 | 每个 Choice 必配 None（以上都不是）选项，并加一道 Noul 守门「是否属于现有意图清单」，答否进发现队列（§6.2、J-10） |
| 中文校准依据 | 已要求单独校准，无外部证据 | 补论文证据 Chinese-Jev（arXiv:2609.36965）；英文结果不得代替中文原文跑分（§6.3） |
| CX 数据边界 | §6.8/§13.2 已写不进第三方，未点名 Jev | 点名写死：Jev 即第三方 API，CX 绝不进 Jev，只做本地/人工编码，无例外（§6.9） |
| Reddit 时间线 | §4.4 仅泛述「遵守当期授权」 | 写死：RSS 2026-11-13 起停止支持、无可用性承诺；2027-01-12 未注册应用被撤访问权；2027-03 公开 Data API 全面关闭（§4.4） |
| 列表编号 | §7.1 步骤误从 6 起、§10.3 误从 12 起 | 两处重启编号为 1–6 与 1–4 |
| GitHub 仓库 | 无 | 新增附录 F：公开仓库 voc-research-workbench 的目的、六层目录与绝不进仓库清单 |

验收新增 J-9（版本锁定执行）与 J-10（None + Noul 守门生效），§12.1 交叉引用同步为 J-1~J-10。
