# M08-D 采样任务契约

## 数据边界

M03 提供 `study_id`、`scope_id`、`scope_version` 和既有冻结时间。任务服务使用这些键读取冻结范围，冻结项目、查询计划及版本、来源与适配器版本、研究目标、UTC 日期窗口、样本目标、逐源上限、查询和页面访问上限、逐单位预算和授权引用。任务创建后配置不可变。控制和读取操作使用可信本机操作者与项目权限，任务服务在采样步骤、继续操作和回读证据前核对当前许可及冻结绑定。来源批准和账号配置若发生变化，服务据当前授权决定能否继续提供回执和恢复执行。

M08-D 的任务状态、请求预约、请求回执和对账历史存入 `m08-sampling/ledger.sqlite3`。这是独立的 v1 SQLite 文件，初始化使用独立的 SQLite application ID，检查意外文件类型，连接启用外键，事务使用全同步写入。M08-A/B 的演示回执保留在 `m08-offline/acquisition.sqlite3`，正式工作库仍使用现有 v8。采样任务通过各任务独立的 v8 工作库复用 M04 的批次和质量检查、M05 的不可变快照及许可、M06 的精确证据区间。任务账本保存合成回执、用量和稳定关联，原文和资格由其对应工作库管理。

任务、请求、成本和输出在本轮均为合成工程用途。正式入口受 G-1 阻断，任务状态中的 `completed` 表示计划的工程检查点已执行完毕。真实 API 请求和真实费用均为零。正式漏斗阶段保留 `null`。工程漏斗通过去重规范 URL、页面回执和精确片段分别计算。文件导入中缺少权威发现或页面访问台账的前置阶段继续保留 `null`。

## 状态转换

| 操作或事件 | 当前状态 | 后继状态 |
| --- | --- | --- |
| 创建 | 无 | `draft` |
| 排队 | `draft` | `queued` 或 `permission_blocked` |
| 预约检查点 | `queued`、`running`、`partial` | `running`。当前授权无效时进入 `permission_blocked`，未知或超出额度时进入 `budget_blocked` |
| 结算已收到的检查点 | `running` | 有后续步骤时进入 `partial` 或回执指明的暂停、阻断或失败状态。末步骤按回执记为 `completed` 或 `failed` |
| 用户暂停 | `queued`、`running`、`partial` | `paused`，正在执行的检查点可记录既有回执并完成结算 |
| 继续 | `paused`、`permission_blocked`、`budget_blocked` | 当前权限通过且没有未明预约时进入 `queued` |
| 取消 | 非终止状态 | `cancelled`，既有预约及凭据留存，已发出的检查点可完成结算 |

`failed`、`cancelled` 和 `completed` 为终止状态。合法状态变更及首次开始、完成时间保留在任务历史中。主动暂停和取消发生于单步边界，不能撤回已经预约的动作。已知错误使用可审计的原因代码记录，来源切换由 M08-B 的许可及错误分类决定，当前任务的后续检查点在开始时再次核验授权。

## 幂等、预算和恢复

1. 创建操作在同一个项目内绑定操作者、创建幂等键和规范化配置。重复相同输入回读已存在任务。完全相同的工作计划用新创建键仍会受到约束。
2. 每个检查点在排他写事务中校验状态、配额和当前授权，生成稳定 `request_id`，持久化 `reserved` 后才允许执行。创建成功后的本机任务查询支持分页，详情按检查点保留可审计历史。查询和页面上限统计计划中的请求数，计量单位由来源定义，两个口径独立。只针对当前来源的单位核对 `authorized` 与已知的模拟 `available`，现有占用和已耗用均计入限制。
3. 需要备用来源时，服务在预算预约前根据主来源回执判断是否发送请求。跳过时写入 `not_dispatched` 事件及零用量回执。
4. 收到可验证结果后先提交 `received` 及回执。随后在同一次事务记录 `checkpoint_persisted`、递进检查点、消除预约和提交 `usage_reconciled`。回执落库后中断可以只做结算。触发补结算的新操作键登记为已使用，重复请求只回读。
5. 计量检查点停在 `reserved` 表示发送结果和费用未知。原键可回读预约，其他运行操作被阻断。即使任务已取消，相同未明请求也不能通过同项目其他任务重发。零计量的本机导入可在重新核验授权后回读 `m08_import_receipts` 补结算。该回执按 `request_id` 在 M04 批次和 M05 快照同一事务中持久化。无有效回执时继续阻断。账本保留请求、来源、次数及用量预约。

当前模拟额度随任务冻结。额度不足时任务保留阻断状态和具体单位。模拟用量按 Tavily credit、Brave request、YouTube quota unit 及适用的来源单位分别记账，费用预算上限固定为真实费用零。页面分组可以在一个检查点内申请多次访问额度，预约上限必须覆盖该组。

## 批次与消费

计划按顺序保存来源发现、许可回源和 M04 导入的检查点。跨搜索引擎保留彼此独立的发现回执，规范 URL 仅用于同一窗口内的发现去重。跨站转载与同文独立发生的身份继续依 M05/M06 的证据规则核验。CSV/Excel 兜底走相同 M04 映射及质量接口，随后由 M05 核验许可并保存原文，按 M06 区间规则回读候选证据。合成数据不参加正式研究分母。
