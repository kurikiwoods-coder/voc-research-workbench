# M06 核心数据接口交接

开发接续先检查 [M06-R 工程审计](../audits/m06-final-engineering-audit.md)、准确的远端提交和该提交的三项 CI。M07–M15 分别按负责人授权启动。正式研究继续受 G-1、项目准入、逐源许可、真实编码、金标准及发布验收约束。SQLite 当前为 v7，计数口径为 `M06-B-F.1`。

| 接续模块 | 已有入口及应绑定的引用 | 后续实现位置和验收 |
| --- | --- | --- |
| M07 注册表 | `RelationStore.definitions`、`task_intent_edges` 和内部 `publish_combination` 提供封版定义、主次任务和原子组合能力。消费明确的 `registry_version` 及稳定定义 ID。 | 建立正式注册表治理、版本差异、审批与发行入口。保持旧版定义和谱系可读，主任务恰一。共享定义只投影获准字段。项目例句和代表原话经项目授权及实时资格查看。 |
| M08 采集 | M03 `scope_id/scope_version`、M04 导入与批次链、M05 原始快照和结构化许可。 | 记录发现 URL、可访问页面、采集回执、UTC 窗口与逐源许可。采样 URL 及页面台账缺失时，C5 对应分母保留 null。 |
| M09/M10 发现 | 合格 M05 原话及 C3 `mention_id/evidence_id`，带项目、片段版、原文摘要和半开 Unicode 区间。 | 绑定算法、输入、注册表及运行版本，输出候选和实际依赖。疑似转载或同义保留待核状态，候选发现不自动确认身份、归属或发布。涉及外部模型须通过逐源及通道批准。 |
| M11 人工审核 | `RelationStore.validate` 提供预检。内部组合事务支持可撤销授权、幂等键、锁内版本核对及精确资格检查。 | 建立可信审核身份、候选队列及联合确认流程。在同一写事务里通过 C2 核验所有实际依赖，使用冻结 V/R、全操作回滚及受控重放。 |
| M12 编码及校准 | 复用 M05 当前资格、M/E、代表 `record_id`、已封版注册表及任务边。合成回执用于工程验证。 | 真实回执固定 S/R/V、索引、模型、题组和校准版，逐项绑定原帖、转载和跨句上下文。保存独立 Choice、Score、Noul 及分片审计。撤销或到期使依赖该输入的决定退出统计，重新授权后须复验或重编。 |
| M13 统计与发布 | `GET /api/studies/{study_id}/denominators` 提供同一证据交集、唯一发生、六桶、排除账及两条对账。已实现工程和隔离合成验证。 | 补齐 M08 台账、M12 真实回执和准入后实现正式发布、历史重核、撤回及重算。保存精确筛选与全部依赖。十万级大范围查询的后台计算需要单独设计，保留响应交付前的当前资格及授权复核。 |
| M14 问卷 | 复用明确版本下的意图 ID、最小证据引用及独立的问卷验证状态。 | 建立题项映射、审核及授权回写。内部原始答卷留在本机，验证状态与发现、编码和发布状态分别维护。 |
| M15 Radar | 复用冻结范围、目录及映射版本、历史 R/V、来源与窗口的同口径切片。 | 分项目校验访问权，再做获准比较。跨产品并集按同一合格证据求交后重新去重，避免相加重叠小计。保持撤销、历史可见性和采样偏差可追溯。 |

读证据先检查项目、精确片段版和成员，再复核许可、隐私及授权。条件随时间变化时，以可追溯的精确证据和当前资格为准。使用 [冻结统计契约](m06-statistics-contract.md)、[接口契约](m06-api-contract.md) 和 [负责人裁定](m06-owner-approval.md)核对边界。
