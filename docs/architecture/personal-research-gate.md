# G-1-PERSONAL 最低准入政策

`G1_PERSONAL_POLICY = DOCUMENTED`，`G1_PERSONAL_IMPLEMENTATION = PARTIAL`，`G-1-PERSONAL = NOT_EVALUATED`。个人版使用一条独立正式准入记录。G-1-P-D 负责同批六项实证，G-1-P-R 负责独立安全复审与最终准入。个人正式研究须等这两步完成。M09 等隔离工程按各模块现有授权实施。商用版沿用原 G-1。[负责人批准](../decisions/dual-edition-owner-approval.md) · [当前实施顺序](../planning/ROADMAP-V2.md#当前接续顺序)

## 判定条件

个人研究正式使用须同时具备受信身份及明确用途、项目和来源资格、实际账户及调用通道审批、当前凭证版本、预算、同一验收批次六项证据及独立复审。部署方式、可用功能与研究发布按各自权限确认。准入与作用范围、有效期、策略版本和证据完整性绑定，经核准撤销或过期后重新判定。

| 检查 | 同一批次的最低证据 | 失败条件 |
|---|---|---|
| C0-1 固定模型与拆分 | 实际通道以 `jev-1.14.0` 运行获准输入，真响应核对精确模型，自动 11 题按 8+3 执行并按题号完整合并 | 请求、实际模型、分片或归属不符，保持阻塞 |
| C0-2 Choice、Score、Noul | 客户端保存可核对的脱敏实际响应，Choice 每选项、Score 每档概率、独立 Noul 概率及档位和题号齐全 | 缺字段记 `schema_gap`，不可由置信度、估算、其他片或其他模型补齐 |
| C0-3 搜索及原话 | 获准 Tavily 或 Brave 发现 URL，经受许可页面或接口回源，最少一条可核对真实用户原话，同时保存采集方式、用途、许可和回源 | 搜索摘要、合成正文、失格来源或无回查路径不能通过 |
| C0-4 真实用量与持久化 | 实际分片用量、预算及预约、SQLite 入账与回读、重启和幂等恢复。实际余额或明确未同步，费用与估算分列。一旦结果或扣费未知，先对账再决定 | 无真实计量、预算未拦截、单次计费重复、回执不一致或未知订单仍可发送均不通过 |
| C0-5 内部隔离及故障 | 合成内部标识在任何外部发送前拦截，实测断网、凭证异常、额度、契约错误、限流及上游故障。失败关闭并保留可审计状态 | 内部数据、敏感输入或权限失效仍可外发，或故障时绕过限制 |
| C0-6 三层与全局召回 | 按原标准验证 2 个产品品类、3 个任务大类和至少 30 个意图，关系完整，固定注册表与索引，Top-K 加 None 不超过 20 | ID 或关系无效、版本及候选不可追踪、按产品硬筛或 Choice 含 None 超限 |

C0-5 与 C0-6 按原规范使用隔离夹具并保留可重复检查的结果，与真实输入、回执和正式统计分域。C0-6 是召回冒烟，M12 的 J-14 和金标准仍独立验收。其他阶段的真实采样、M12 校准、M13 发布和 M14 问卷验证仍依原标准。[原验收矩阵](../requirements-matrix.md#可机读的需求映射)

## 暂停与恢复

负责人通过 PRODUCT-REALIGNMENT-V1 保留 G-1 主动治理及后续实证的暂停状态。**G-1-P-D = BLOCKED，G-1-P-R = NOT_STARTED，G-1-PERSONAL = NOT_EVALUATED**。Personal V2 工程、草案及历史证据照常保留。PackyCode 账户条款待决事项仅约束该通道，额外专项调查停止。M11 独立工程就绪后，M12-A 获单独授权才做最小修正。M12 的真实研究及校准前恢复 D 同批六项与 R 独立复审。[正式 ADR](../decisions/product-realignment-v1-owner-approval.md#personal-最小准入修正) · [当前接续顺序](../planning/ROADMAP-V2.md#当前接续顺序)

未来所选 Personal 通道按实际账户和用途核对 API 权限、模型身份及能力、输出契约、真实用量及费用、数据保护和预算。企业级深度供应商审计及重复行政审批不适用默认流程。具体条款、法律或安全要求有必要时仍须核验。明确禁止当前用途的通道继续关闭。凭证更新后的绑定与变动项核验依 [适配器契约](ai-model-adapter-contract.md#m12-a-最小接入范围)处理，当前运行代码及审批规则维持原样。Business Edition 沿用原严格治理。[商用原门禁](business-research-gate.md)

## Personal V2 批次治理

Personal V2 沿用 `G-1-PERSONAL` 正式门禁和 C0-1 至 C0-6 的原有判定。负责人通过当前可信本机 Owner 会话签发受限预准入批次，绑定冻结研究范围、用途、实际账户、凭证版本、供应商通道及 UTC 窗口。现有 G-1-P-D 服务负责逐槽授权、预算预约、唯一发送权、档案及对账。批次只为准入取证，数据和计量保留在验证域。商用 G-1 使用其既有审批及验收政策。[商用原门禁](business-research-gate.md) · [Personal V2 授权草案](../evidence/g1-p-d/personal-v2-authorization-draft.md)

现有四槽草案的模型路径固定为 PackyCode `typesafe-officially`、`/v1/systemone`、`jev-1.14.0`。负责人须独立核准当前账户 API 权利、通道及条款、可处理数据、逐源许可、最小脱敏载荷、费用和适用的剩余风险。必要条件缺失、禁止、失效或与当前账户和凭证版本不匹配时执行关闭。非强制未知事项按个人版审批规则记录其影响、保护措施、责任人及复核期限。[审批与风险](personal-approval-workflow.md)

2026-11-27 负责人冻结 Personal Edition 的 G-1 供应商治理范围。现有账户信息、适用的公开条款和可信本机 Owner 基础核验即可作为账户及用途证据。Owner 在现有证据注册表记录条款版本、适用账户和用途、核验结果及有效期。额外的供应商书面审批为可选材料。账户或用途无法确认时保留实际状态，适用条款明确禁止时阻断。Owner 的费用风险接受仅适用于已批准的费用风险。来源许可、脱敏、凭证安全、预算和实际费用对账继续按原标准核验。[审批与风险](personal-approval-workflow.md)

本机限制覆盖批准次数、载荷、发送前预算预约及不确定结果后的停止和对账。供应商侧可执行限制只按能核实的证明记录。缺逐请求输出硬限制或可确认的最坏扣费边界时须如实披露剩余风险，并由 Owner 明确批准当前账户和固定模型路径的本机限制、预算及风险范围。回执仍须保存实际分片用量及实际账单。超额、扣费或结果不明、档案或对账不一致时暂停批次，核对后才能按原权限决定接续。证据中分别标明本机限制、供应商限制、费用估算、实际扣费及余额状态。

透支、自动充值和无上界扣费分别登记三态。JSON `false` 表示有适用证据确认不存在，`null` 表示未知，`true` 表示已知存在。只有 Owner 在当前账户、凭证及固定通道的风险证据中指明实际未知项、给出接受理由和明确边界，并批准正值的剩余风险金额上限时，才可接受 `null`。任一项为 `true` 时阻断。模型两片预约加剩余风险上限须落在已有证据的专用令牌额度内。控制台配置 USD 2 时，仅按配置额度登记。供应商侧硬扣费上限另凭可执行性证据判定。

## 证据复用

1. 为个人版开一项确定的正式验收批次，冻结项目、范围、用途、批准账户、凭证、模型、题组、证据摘要、规则版及窗口。六项在该批次逐项决议。允许的历史材料通过带来源、原批次、取证用途、摘要、有效期和复核者的只读引用纳入。规则不允许归入、用途或输入等级不同、停用、撤回、到期及无法重现时，该项继续挂起。
2. PackyCode 的合成 8+3 回执只证明原固定合成输入在当时通道上的模型、字段及实报用量能力。原费用补证可作为历史计量旁证。正式真实语料的调用、完整性、预算及回读须有适用的正式证据。旧通道或轮换凭证不得继承审批。
3. 既有 Tavily 搜索与真实原话可先核对搜索结果、回源路径、来源许可、原文摘要、查询与时间窗及用途。当前规则明确许可且可核验时，由新批次记录纳入决定。回源和许可无法重验时记缺项。工程夹具或受限快照不能填充真实原话。
4. C0-5 和 C0-6 可复用已通过且仍适用的离线证据。核对原始产物摘要、来源批次、检查覆盖、版本和适用范围后，在当前批次登记负责人复核和引用。保留原始判定及产物供 G-1-P-R 复查。只有已登记并可核验的证据参与同批判定。[Windows 11 离线实证](../evidence/g1-p-d/d-l-windows11-deployment.md)
5. 六项的当前证据不足时列明实际缺口。需要网络验收时，仅在 G-1-P-D 获得独立有期限的执行授权后运行最少必要的请求、预算和来源。原 PackyCode 合成授权已耗尽。原有历史账本保存原状态。[合成记录](../evidence/g1-rb-p/README.md) · [费用补证](../evidence/g1-rb-f/README.md) · [历史搜索证据](../evidence/p0-0/tavily-live/README.md)

## 预准入验收与最终放行

G-1-P-D 在验证专用审计域收集证据。现有四槽草案依次登记 Tavily 搜索、同一合格命中的官方回源、PackyCode 前 8 题、PackyCode 后 3 题。每槽最多一次，按实际证据核准后续槽。恢复时以经授权的实际模型及通道为准，调整必要的执行配置，仍按同批六项原标准验收。额外请求须由负责人另行批准。六项均有合格同批记录后交 G-1-P-R 独立复审。复审应逐项核对原验收标准、复用证据适用性、账户和凭证、授权及费用对账、许可及脱敏、异常与暂停记录，最终记录适用范围内的 `PASS` 或实际阻塞项。准入前正式编码、发布回执和业务分母保持关闭。

| 个人版门禁记录 | 必须保存 |
|---|---|
| 准入命名空间 | `edition=PERSONAL`、`gate_id=G-1-PERSONAL`、状态、策略版本、验收批次、复审结论，以及形成及失效时间 |
| 使用绑定 | 项目、冻结范围、用途、可信操作者及审核方、供应商、实际通道、固定模型、账户和凭证版、预算范围 |
| 审计引用 | 六项指向本机证据的受控引用、历史纳入决议、审批及有效期、可接受风险与撤销记录。投影仅展示授权范围内的最小信息 |

## 日常 API 生命周期政策

G-1-P-R 复核日常用途的适用范围和风控前提，后续 M02 API 配置中心沿用现有凭证控制并按独立授权接续。日常授权绑定实际账户、供应商及通道、凭证版本、项目和用途，设置有效期、用量和费用约束并保留实际账单对账。

供应商、通道、模型和数据处理方式保持一致时，按现有授权管理日常凭证及额度。轮换或撤销 API 密钥、补充或调整额度、调整有效期及重新绑定凭证，按受影响范围执行最小连通性验证并复核授权范围。密钥失效或余额不足时暂停受影响任务，更新并验证后只恢复仍符合资格的任务。此类维护沿用已适用的六项验收证据。供应商、端点、模型或数据处理方式发生实质变化时，针对受影响的接口、隐私、费用和准确性重新核验。保留历史记录、模型版本、账单及来源溯源。[M02 接口规划](ai-model-adapter-contract.md)
