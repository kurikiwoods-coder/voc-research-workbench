# G-1-P-D-E 受限预准入账本与迁移草案

2026-11-26 · Phase 0 · **待负责人独立批准**。草案以 `9f21ffcfd2d9e03d998da455f2d5b030ceacba2d` 为基线。当前工作库仍为 v9，`personal_pre_admission` 仍拒绝执行。[阶段复验证据](../evidence/g1-p-d/phase-0.md)

## v9 复用与迁移必要性

C 阶段已有可信本机会话、Owner 和项目权限、冻结范围、不可变审批及证据、风险判定、DPAPI 和 SQLite 当前凭证锚。v9 的批准材料仅包含既有整数 Token 上限，每项目及冻结范围有一个当前凭证锚。审批中心当前管理 PackyCode 凭证。新链路的 Tavily 账户和凭证必须单独受控，回源必须独立校验具体来源许可。旧全局搜索密钥不能代替批次授权。

旧诊断账本没有 D 批次、审批、凭证、冻结范围、来源和多维费用边界。M08 模拟采集预算使用另一连接，预算模型限定合成用途。将 D 状态与这些账本分开写会在进程退出或资格变化时留下已预约但没有对应请求状态的窗口。D 的预约、当前资格、回执、撤销和对账需要同一工作库的可恢复事务。设计中复用 v9 表和校验服务，追加受控增量 `010`。

## 调用链与信任边界

1. 可信工作台会话解析 Edition、操作者、Owner、项目及冻结范围。服务端按命令固定 `personal_pre_admission` 和 D 验收用途，客户端只可引用批次及已获准操作。沿用现有授权与审计机制。
2. 服务端核对批次授权、当前审批、风险、账户、精确通道、模型、当前凭证锚、策略版本、UTC 窗口、逐源许可和分类。最终载荷由服务端依批准材料生成并核对摘要。内部 CX、内部机密、原始问卷、未授权敏感内容及不确定来源在传输前阻断。
3. 搜索仅接受获批查询和白名单。回源绑定同一命中链路、最终 URL、许可及准许的网络操作，越界跳转停止。模型操作须等回源后分类、脱敏和题组冻结，再获得精确载荷授权。历史搜索或回源可以分别复用，须逐项复核当前用途、来源、许可、时间窗及内容摘要。
4. 复用现有 Jev 请求构造、响应校验及自动 8+3 分片。Choice、Score、独立 Noul 保留原契约，11 道判断题与 Choice 题的 11 个已知候选分开校验。精确绑定 `typesafe-officially` 和 `jev-1.14.0`。复用 Tavily 和回源适配器的纯构造及校验能力。既有发送入口继续执行现有门禁。D 发送仅由受限服务命令交给固定端点传输，工程测试注入隔离替身。
5. 凭证读取仅在内部发送服务中进行，依可信当前锚打开获批版本。核查同一 SQLite 事务内的锚与计划指纹。只归档脱敏标识、摘要和回执，客户端只看服务端状态。原始凭证及密文留在受保护本机。

C 的材料登记目前由受保护本机文件提供。D 需使可变的风险决议、来源许可及撤销在预约和回执事务内有可排序的权威状态。草案沿用 C 的材料校验及摘要引用，在工作库记录经受信更新的材料版本与撤销序列，逐次比对当前材料；遇文件、数据库、恢复水位不一致时暂停。事务只保证工作库内的先后顺序，外部材料与密文的生命周期仍须在发送与恢复边界重新确认。

该运行域的产物只能进入 D 验收账本。正式编码、发布及统计仍由原运行域和门禁控制。D 产生的正式研究分母为 0，原未放行统计保持 `unavailable/null`。C0 证据须分辨本批正式接口、获准复用历史、合成夹具、本机工程回归和缺项。C0-5、C0-6 只有在正式批次当前资格复核后才能计作该批证据。C0-6 固定原注册表与索引版本，复用稳定意图 ID、2 品类、3 主任务、至少 30 意图及全局召回，Top-K 加 None 不超过 20。

## 批次、发送与对账

| 对象 | 状态与约束 |
| --- | --- |
| 批次 | 未审批 → 已审批待执行 → 执行中 → 待对账或证据待复核 → 已完成。各非终态可按当前理由暂停或阻塞。撤销追加不可变事件并终止新发送，已发请求仍可对账。恢复执行须重验权限、窗口、锚和预算。合成批次有独立标识，仅在隔离库通过替身执行。 |
| 授权 | 一批可追加多个逐操作授权。每项绑定项目、范围版本、Owner 决议引用、证据、来源许可、账户、凭证、通道、模型、预定操作、批准载荷摘要、窗口与限额。策略、载荷或凭证变更须追加审批。批次预算固定，增补授权仍受累计上限和审批约束。 |
| 预约 | 已预约 → 发送已提交 → 已结算或待对账。只有能够证明未发送、且没有并发发送权时才可释放。供应商实报、估算、实际扣费和余额分项报告，缺项保持未知。实报超限保留真实审计、阻断后续请求并进入对账。 |
| 回执 | 保存逻辑请求和预约引用、供应商请求 ID、模型、请求与响应摘要、三种 Token、用量、估算、实扣、币种、对账和证据引用。回执写入幂等。响应后失格时保存用量及费用，凭证轮换、审批撤销或许可失效写入阻塞原因。同批证据资格单独判定。 |

逻辑请求按服务端不可变授权和操作槽位唯一，冻结批次、账户、通道、模型、凭证版本、题组版本、分片和规范载荷摘要。相同槽位的摘要变更返回冲突，重复提交读取既有状态。预算按批准的请求数、搜索 credit、输入、输出和总 Token、单次与累计金额及账户供应商额度并行约束，金额以审批指定币种及整数精度表示。预约用最坏合规费用，按整数边界验证且拒绝溢出。供应商可执行的输出和费用上限未核实前阻断真实发送。

- **预约事务**使用工作库 `BEGIN IMMEDIATE`。同一连接校验当前 C 审批、资格与额度，创建唯一逻辑请求及原子预约。并发重复请求复用该记录。
- **发送事务**在已预约后再次校验当前资格、指纹和唯一发送权，提交后释放写锁再发送。撤销先于发送事务提交时拒绝传输。发送权已提交后出现撤销则保留在途记录并阻断后续操作。外部传输与数据库提交之间存在无法原子覆盖的窗口。
- **回执事务**原子写入脱敏回执和结算或待对账状态，同连接重验当前批准、凭证和来源。失格回执只进入审计。双分片保留独立回执，缺片、`schema_gap` 或题号不全时，不生成合格合并结果。
- **重启恢复**扫描预约和发送标记。仅预约且能排除在途发送时，可在重验后释放或继续原逻辑请求。已持久化发送权、超时或响应后提交失败一律冻结该预约，按未知结果人工核对。禁止自动重试未知付费操作。供应商原生幂等能力当前未知，真实执行申请须分别核实 Tavily、回源及 PackyCode。工程只承诺本地唯一记账与保守暂停。

## v9 → v10 迁移提案

| 范围 | 草案 |
| --- | --- |
| 库目标 | 按可信应用 ID 和 Edition 显式选择迁移目标。Personal 工作库追加 v10，Business 保持 v9，诊断库及合成契约库保持 v1。合成 D 回归另建 Personal 测试库。旧 v9 客户端遇到 v10 工作库须拒绝写入。 |
| 表及关系 | 追加批次、追加式批次授权与状态事件、逻辑请求与预算预约、回执与追加式对账、C0 证据关联。外键绑定项目、范围版本及审批材料，唯一性保护单操作槽位、预约和回执。保留 v9 的批准、撤销与原始 ID。 |
| 凭证 | 保留 v9 PackyCode 历史审批及锚的语义。使用现有 DPAPI 能力新增精确供应商和操作级作用域，通过受控当前锚引用同一信任链。旧 C 批准仍按旧条件读取，建立 D 执行授权时逐项确认。 |
| 兼容 | 不修改 M06 数据结构、统计契约或原工作台历史记录。迁移初始无 D 批次或执行许可。原有 C 界面、快照及审批 API 回归作为兼容验收。 |
| 执行 | SQLite 在线备份覆盖活动 WAL，做还原演练并记录完整性、外键及稳定 ID 核对。迁移采用现有版本检查和串行事务，DDL 和 `user_version` 一起提交。测试断点、双进程竞争及重复启动。批准前不创建迁移脚本、不部署。 |
| 回滚 | 提交前失败由 SQLite 事务回滚至完整 v9。已提交但 D 未使用时，先停服务，在新隔离路径恢复并核验 v9 备份及凭证锚，原库留存。产生 D 历史后暂停运行域并保留 v10 审计，优先向前修复。灾难恢复期间须核对备份与最新授权撤销、凭证轮换和对账记录，无法证明连续性时拒绝已有批次继续执行。 |

迁移合并前须在原生 Windows 11 隔离运行完成 v9→v10、旧客户端拒开、Business v9、诊断及合成契约库 v1、活动 WAL 备份、故障回滚和恢复后撤销复验。随后依阶段验收覆盖受信身份、来源、预算、并发、幂等、故障、DPAPI 和六项证据。三项对应 CI 及全部工程验收通过后，D-L 才能提交真实执行审批。
