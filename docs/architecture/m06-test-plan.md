# M06-A 反例推演与验收矩阵

以下全为纸面合成输入及预期，供 M06-B 逐条质疑。案例中的“已发布”假设未来已具备正式准入、同版完整回执及审批，仅用于演算；当前正式 API 应返回 unavailable/null。案例彼此独立。数对 (E,P) 依次为 N_eligible_dedup、N_published_classified；e1 等小写标识仅为示例证据。

## 可手算反例

| 编号及输入 | 应形成的关系或事件 | 预期状态与计数 | 要捕获的错误 |

| 1　营养秤用户与空气炸锅用户各自说“断网也能操作” | 两次独立发生 m1、m2，各有本产品证据，同一意图 I1、主任务 C1 | 各发布，(2,2)，各产品 1，主类 C1=2 | 同义合并成一人；按产品复制 I1 |
| 2　一行“断网也能称重，还想导出记录” | 同一 record，两个码点区间 e1/e2，两个 mention 与两个意图 | 若各自完整发布则 (2,2)，来源行数 1 | 按行计 1 或覆盖原话 |
| 3　I1 同属 C1、C2 | 两边有效，仅 C1 主、C2 次；m1 发布为 I1 | (1,1)，主类 C1=1，C2 关联明细=1，主类 C2=0 | 两个大类各加 1 |

| 9　两个项目导入同一公开原帖，共用 V1 | S1/m1、S2/m2，授权独立，各自的冻结/证据外键 | 各项目假设已发布则各 (1,1)；持 S1 查 S2 的 E 返回 404 | 合并两项目人数或泄露对方证据 |
| 10　同一研究冻结范围从 v1 秤扩展为 v2 秤和炸锅 | 各批绑定各自 scope；旧批 m1 秤，新批 m2 炸锅 | v1 (1,1)，v2 (1,1)，v1 查炸锅 (0,0) | 从当前范围反写历史产品 |
| 11　V1 的 I1 在 V2 合并入 I3 | 留 I1 墓碑、映射及旧回执；旧报告固定 V1；V2 须重验 | V1 (1,1)；V2 未重编时 (1,0)，重编并发布后 (1,1) | 静默改写旧分类或跨版拼概率 |
| 12　候选任务已写、写意图主边时失败 | 一笔事务包含两候选、关系、全局发行和审计 | 失败后仍旧版，二者原状态，(1,0)；同键重试成功最多一版，片段仍待发布 | 残留孤立已确认任务或借确认自动发布 |

| 14　m1 有秤与炸锅两条已审产品边，m2 仅秤 | 每条边有本身合法证据 | 各已发布；秤 (2,2)，炸锅 (1,1)，两品类并集 (2,2) | 小计相加报 3 |
| 15　开放研究“希望社区活动可延期报名” | scope_product 空，m1 有合法来源、I1 和主任务，产品边空 | 项目 (1,1)，按任一具体产品筛为 (0,0) | 虚构通用品类或丢掉非产品需求 |

| 17　来源 A 的 e1 仅支持秤；来源 B 的 e2 仅支持炸锅，均属 m1 | 来源和产品条件须匹配同一证据 | A+炸锅 (0,0)，B+炸锅 (1,1)，全项目 (1,1) | 跨不同证据拼接筛选条件 |
| 18　一条回执显示 None 但缺 Score 分片，另一条完整 Noul 否且低置信 | 两条分别按优先级只归一次；第三条从未开始编码 | (3,0)，partial_or_schema_gap、none_unknown、other_pending 各 1 | 将两个异常都入桶，把未启动报成失败 |
| 19　两个真实用户说出完全相同的长句；第三行疑为其一的转载 | M05 文本同组，前两次独立发生分别保留，新疑似输入暂挂 | 若前两条发布则 (2,2)，第三行身份待核在外；换组主不改 m1/m2/e1/e2 | 用文本哈希或组主作为片段 ID |
| 20　同一表达含 emoji 和组合字符，规则从整段改为两个目的 | 对原文按码点复核，父版 1 个 M，本版 2 个新 M；同命令重放命中相同 ID | 父版按原决定 (1,1)，新版未编码 (2,0)；两者确认后 (2,2) | 按 UTF-16 或归一后文本截取、把两版累加 |
| 21　22:00 检查后撤销，或写事务跨 UTC 留存日界 | 写锁内重新检查所有输入，展示时再核；撤销先提交则拒绝写 | 无剩余证据则当前 (0,0)；重授权后的新回执独立评判 | 直接复用 HTTP 200 的缓存、旧报告明文 |
| 22　同幂等键断连重试；不同命令竞争同一预期 V | 同键同内容只取原结果，同键异载荷拒绝；不同键旧版写返回 409 | 同一命令只增 1 版；未出现新发生，E、P 均不因重试变化 | 多次发行、重复挂边 |
| 23　旧范围有未知产品串，又有已发布范围引用欲停用的节点 | 前者未解析，后者须阻止失效变更；仅新冻结引用可核的确认节点 | 不凭名称补边；新正式品类结论不可用；旧版可核历史数原样回放并重验许可 | 用默认产品填充、通过全局停用破坏已发布研究 |
| 24　已知候选数依次为 0、19、20、21，另有低相似与索引异常 | 0 不发 Jev；19+None；20/21 都缩至 ≤19+None；保存 V/index/排序 | 单凭召回所有 P=0，低相似进入人审，异常待处理 | 发 21 选项、把召回错误记作 Jev 判 None |

**已有 C0-6 的证据边界。** [现有代码](../../src/discovery/recall.py)在内存 SQLite 建 2 产品、3 任务、30 合成意图；字符 TF-IDF(1–3)、20 维截断 SVD（seed 47）、归一化余弦，全局 Top-12 两次跨产品命中。输出 sklearn/索引/注册表版本、候选与分数，Choice 含 None，noul_guard 为标记。它只验证召回可跨产品，未实际调用独立 Noul 或以人工金标准评测召回。本轮依据代码和原验收记录，没有重新运行冒烟。后续 J-14 对已知样本用命中真实目标的数量除以适用已知查询数，未知样本及跨品类子集分别给分母，避免混用；模型最终分类另报 Macro-F1。

**实施后的工程边界。** 在隔离空库/v6 副本验证 FK、迁移崩溃与回退；双连接模拟撤销对写、到期、两人确认以及断连重放；契约测试检跨项目 404、失格 409、无权原文、工程/正式隔离；桌面与窄屏从筛选一路走至证据、撤销后重开。使用合成夹具验证的计数永远保留 synthetic 标记。以上不构成本轮业务测试或正式验收。
