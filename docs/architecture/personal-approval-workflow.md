# 个人研究审批及供应商风险管理

个人 Owner 可以在规划中的审批中心对获准项目完成内部审批。服务端验证 Owner 身份、项目和操作授权，并把批准范围、依据、通道、账户和凭证版本绑定到一次不可变审批事件。当前 PackyCode 账户为 `PENDING`，独立合成接口契约为 `PASS`，个人版准入尚未评价。[个人准入政策](personal-research-gate.md) · [实现切分](../planning/g1-personal-implementation-plan.md)

## 强制证据和可接受未知

| 必须有可核证据 | 处理标准 |
|---|---|
| 当前供应商账户与 API 权利 | 核账户能力、实际通道、固定模型和凭证版本。证明适用条款允许拟用数据、目的、频次及必要下游处理 |
| 合法使用和逐源授权 | 登记合法处理依据，分别核采集、保存、转换、分析和外发许可。来源、文本角色、当前资格、项目、时限、署名与删除义务可追溯 |
| 数据保护 | 确认实际待送内容属于获准公开且已经必要脱敏的数据，逐次核输入及真实上下文。内部 CX、企业私密资料、问卷原始答卷和未获准敏感个人信息禁止外发 |
| 可控用量 | 记录可核的预算、计费单位、批准额度、暂停及未知计量处理。实际用量、估算费用、真账单和余额各自留证 |
| 可信审批 | 登记审批人、政策和证据版本、用途与项目范围、审批时点、到期、可撤销状态及账户绑定。来源和证据失效能阻断续跑及不再合格的结果消费 |

企业级 DPA、ZDR 资格、完整上游供应商名单、精确处理国家或地区、企业采购程序和多人审批在个人政策中一般可列为非强制事项。无法取得且经评估无碍强制约束的事项记录 `UNKNOWN`，由 Owner 附理由、影响范围、保护措施与复核期限确认风险。若具体条款、数据类型、第三方限制或法定义务使其中任何一项成为必要条件，该项按强制证据处理。合法性、来源授权、账户权利或安全基础无法确认时保留阻塞。明确禁止、过期、撤销或与实际通道不符均不得接受为替代。

## 审批工作流

1. Owner 从受信会话选择已获准项目、用途、精确范围及实际供应商，确认拟使用的数据、处理方式、预算、暴露边界和证据路径。
2. 服务端检查材料结构和当前有效性，逐项呈现已核、缺项、`UNKNOWN` 与阻塞原因。证据文件、凭证明文、凭证指纹和完整账单留在授权服务端。页面使用最小可见状态和安全引用。
3. 记录必要条件和每项非强制风险的选择、理由、缓解、有效期及责任人。确认要求真实人工操作，关联当前账户、端点和凭证版。相同幂等请求返回在当前权限下可见的原结果，载荷变化走新审批。
4. 事务内复核先决条件并追加审批，保留先前历史。撤销、过期、策略或条款变化、凭证轮换及实际通道更换会令当前决定失效。撤销、变更和失败原因写入本地审计；后续研究逐次检查当前状态。
5. 查询、导出、回放、任务预约、异常重试与恢复均按当前权限、版本、精确项目、材料及作用范围复核。曾经批准只用于解释历史，实际调用仍要求当下放行及 G-1-PERSONAL 适用操作。

| 最小审批输入 | 计划字段 |
|---|---|
| 作用范围 | 产品版本、项目与确切范围版本、用途、来源或用途边界、供应商、实际上游与通道、模型、服务端账户和凭证版本引用 |
| 授权及风控 | 证据引用及摘要、条款版本、必要项逐项核验、风险项与 `UNKNOWN` 原因、保留/删除规则、脱敏范围、预算 |
| 事件与投影 | 可信 Owner、政策版本、确认及失效时间、撤销事件、父版和幂等键。受权投影仅返回当前可披露的状态、原因及引用 |

后续 UI 的「风险接受」需展示适用范围和期限。名单或条款版本仍缺时原样展示状态。商用审核记录、个人审批和一次性合成账本独立保管。批准供应商仅满足准入的一项依赖，G-1-P-D 与独立复审分别留证。
