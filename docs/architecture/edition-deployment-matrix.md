# 产品版本与部署组合

产品版本决定研究用途、授权及准入策略。部署模式决定执行位置、连接范围和凭证保护。四种组合进入规划；本期工程只沿用既有本机回环环境，双版本策略和云部署分别实施。[双版本政策](edition-policy.md) · [后续产品化](../planning/productization-roadmap.md)

| 版本／部署 | 计划使用 | 准入及部署条件 |
|---|---|---|
| PERSONAL／LOCAL | 个人电脑全功能研究工作台，按项目授权启用 | G-1-PERSONAL、可信本机 Owner、回环与设备边界。Windows 凭证继续使用 DPAPI CurrentUser |
| PERSONAL／CLOUD | 获准的个人 VPS、手机访问、跨设备同步和全天候任务 | 同样适用个人准入。另经云安全设计批准后启用身份、HTTPS、密钥保护、项目权限、备份、同步和任务恢复 |
| BUSINESS／LOCAL | 企业授权设备或本机环境中的组织研究 | 原 G-1、组织身份和数据边界，Windows DPAPI 继续使用普通授权用户上下文 |
| BUSINESS／CLOUD | 企业治理下的云端工作台 | 原 G-1、商用合规和组织权限，另经云安全部署及数据所在地审查 |

## 本机与未来云端的兼容接口

- 部署启动时由服务端读取并核验版本、模式、身份来源和凭证后端。部署切换由受信配置和审批办理。部署设备及会话不改变数据或商业用途许可。
- 当前 HTTP 保持回环、受信 Host 和 Origin、写入限制及响应无缓存。未来本地所有者由受信初始化和授权会话映射至现有项目角色。回环连接本身只负责网络边界，身份需另核实。
- CLOUD 另行设计可信身份、HTTPS、最小权限、设备撤权、会话、密钥管理和轮换、备份与恢复、日志脱敏及数据留存。现有回环 HTTP 服务不直接暴露公网。其他平台采用单独审定的凭证保护，DPAPI 密文不作为跨设备同步材料。
- 定时任务和 24 小时监控在每次预约和出队时重验项目、版本、身份、逐源许可、账户、凭证、有效期、预算和撤销。移动端和同步只投影获准字段，使用精确版本及依赖做审计和冲突处理。内部 CX、企业私密数据、受限原话与原始答卷沿用本机保留条件。
