# M07-C 版本、谱系与接续接口

## 封版与比较

- SQLite v8 沿用 M06 唯一注册表版本谱系。对外版本查询沿父版本回溯，版本顺序由谱系决定。历史定义及主次任务边锁定精确注册表版本。
- 历史与版本差异按稳定 `intent_id` 对比共享白名单字段及封版谱系。任务名称、定义、纳入和排除规则、独立问卷状态及分类归属可回查。
- 新定义、改挂、合并、拆分、停用和恢复先形成项目私有提案。恢复依据旧版定义起草，提交时仍需锁定当前基础版本。仅恢复当前仍有效的任务归属，失效主任务留待确认。恢复复制定义，不复制代表证据、授权、问卷验证结果、编码或模型校准。
- 谱系提案记录前序或后继稳定 ID、项目、理由、提出者、时间、基础版本及修订历史。输入边须可追溯。合并与拆分检查自环和可见的已封版及项目待审谱系。M11 接续联合审核时须在实际发行事务内复核完整谱系。

## 草稿与 M11

局部受理状态为 `draft → submitted → withdrawn` 或 `draft → withdrawn`。编辑追加修订，使用预期注册表版本、预期修订和项目内幂等键。撤回使用当前注册表版本及最新草稿修订，包括已过期的基础版。变更理由及提交者为项目私有。无主任务可以保存候选。预检复用 C4 任务边、实时资格及三次独立代表发生规则，返回 `formal_issuance: false`。

项目草稿需要服务端可信的整项目 `read`、`validate` 和 `registry_draft` 授权。候选精确证据引用另按 `(segment_revision, mention_id, evidence_id)` 校验。失权或失格引用从详情投影移除。预检仍按原依赖执行资格检查。默认应用启动没有草稿权限授予器。

共享读接口使用 `GET /api/registry/versions`、`/intents`、`/intents/{intent_id}`、`/diff`。受权项目从 `GET /api/registry/projects` 选择。草稿列表、详情、修订历史、预检、提交和撤回位于 `/api/studies/{study_id}/registry/drafts`。写路由使用回环、Host、Origin 和 `X-VOC-Action` 检查。请求和响应按本机治理接口的无缓存约定处理。正式联合确认、发布及审批身份交接保留给 M11。

## M09 至 M12

`RegistryVersions.consumer(registry_version, limit=25, offset=0)` 提供工程消费契约。调用方须传精确封版版本。结果只含已确认意图的共享定义、稳定 ID、主次任务、生命周期、验证状态、获准示例和安全的版本信息。候选和项目私有依赖不进入该结果。全局意图消费没有产品硬筛选。正式模型消费还需通过 G-1、逐源和通道授权、版本匹配与所属模型验收。

新注册表版本可能影响 Embedding 索引、全局召回、Question Set、金标准、概率校准和历史可比性。下游索引和模型题组锁定实际 `registry_version`，版本恢复或再次发行后单独复验。J-14、真实模型及重新校准留 M12，问卷回写留 M14-E。
