# 方法论与红线

以下不是建议，是工作台的系统级约束：能写进流程与校验的都写进去，不靠人记。违反任一条的数据批次不得进入统计与发布。

## 方法论红线

- **定性不推比例：** 论坛与评价的定性结论不能推断各类用户占比，不能当完整买家画像；所有汇总按来源分开报 n、日期与分母，绝不混算一个「总体占比」。
- **Jev 概率 ≠ 准确率：** confidence 0.9 不等于 90% 正确；低置信条目先进复核队列，不直接进统计；放量前必须有金标准一致率。
- **口径一致才可比：** 定义不一致的数字绝不并列引用（例如同一页面月搜索量与周搜索量口径不同时，只用口径一致的序列并加注说明）；趋势只比同口径序列。
- **证据可点回：** 仪表盘与报告里的每条结论，必须能点回原文、链接与批次；点不回的结论不发布。
- **旧款不套新款：** 旧型号的评价与客诉结论不得直接套用到新型号；批次登记必须带产品型号。
- **模拟不冒充真实：** 模拟池、模拟人格答案、生成器预估分布一律标注「估计 / 模拟」，不进真实反馈章节，不与真实回收混排。
- **小样本要标注：** 细格样本少于 10 条显示「数据不足」，不给百分比与均值；每批自动编码随机抽查 20 条，正确率低于约 80% 时该批标注「谨慎使用」。

## 合规与数据边界

- **Amazon 不爬：** 不建爬虫、不买代爬服务；只走四条窄路（见 docs/sources/amazon-narrow-paths.md），每批留采样登记。
- **所有来源按许可快照与证据追溯：** 禁止绕过访问控制；搜索引擎片段不得代替用户原话；无可核验证据的内容不进入 VOC 主统计；Reddit 仅为可选适配器，失效不阻断工作台。
- **内部数据不出境：** 内部客诉（CX）先匿名化再进系统，不直喂任何第三方服务；只做痛点排序，不推满意度。**CX 绝不进 Jev**（Jev 走 TypeSafe 托管 API，同样算第三方 API），不设例外。
- **GitHub 只作信号：** 开源生态内容是领先用户信号，不进漏斗、不推规模与付费意愿。
- **脱敏：** 入库前作者名哈希化；去掉订单号、邮箱、地址类字段；公开站外内容保留原文链接即可，不存作者画像信息。

## 证据等级

A = 可作主要依据；B = 对照与三角验证；C = 只作信号 / 痛点排序，不推比例。证据等级随来源与批次定级，统计时按级过滤。

## 问卷纪律

选项必须来自原话归纳；一道题只验证一个发现；多选题「最多选 N 项」题面写清，回收分析时剔除超选回答；人口题只放一道、非必填、放问卷末尾；不收集邮箱，保持匿名；预估答案必须标「估计」；发布四道门：模拟预检 → 2–3 人真人试填 → 正式投放 → 回收回灌。
