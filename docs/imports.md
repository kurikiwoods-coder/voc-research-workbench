# 本机数据导入

在「研究项目」打开课题并冻结本次抽样范围，再点「查看数据导入」。也可以从导航进入「数据导入中心」，主动选择项目与一个已冻结的范围版本。已归档项目可以查看历史批次，恢复后可导入新文件。

1. 下载 [CSV 模板](../examples/import-template.csv) 或 [XLSX 模板](../examples/import-template.xlsx)。保留表头，填写研究数据，也可上传已有表格。支持 UTF-8、UTF-8 BOM、GB18030，以及逗号、分号、制表符和竖线分隔。XLSX 可选择不同工作表。
2. 选择或拖入文件，点「上传并解析」。每个文件最多 8 MiB，单表最多 5,000 条、64 列。XLSX 至多 40 个工作表，每张表的物理行号上限为 5,001。跨行 CSV 原话会保留换行，行号指向记录的起始行。
3. 检查自动建议，手动将一列映射到「用户原话」。任意未映射列会保留在扩展字段中。为含有非公开数据的文件选择适当的批次隐私等级，行级识别和内部 CX 规则会提高保护级别。原文件及扩展字段只留本机，导入前应对内部材料按原治理要求脱敏。
4. 点「检查数据质量」，核对原话样本、目标项目、冻结版本及各类计数。可以返回修改映射，或从首页的待导入文件重新打开。
5. 点「确认导入」写入本机批次。记录详情可按状态筛选，错误报告只含工作表、行号、状态和问题编号等定位信息。修正原文件后可重新上传。批次撤销前会询问，撤销使该批次退出后续处理入口，保留本机原文件、明细和审计记录。

## 记录状态

| 状态 | 含义 |
|---|---|
| 结构合格 | 通过本机结构核对，作为后续审核候选。 |
| 待审核 | 原话可读取，来源类型、发布时间、链接、许可、隐私或范围等仍待核对。 |
| 疑似重复 | 同表已出现相同规范化原话，或同来源类型与外部记录编号。记录保留在批次明细。 |
| 异常拒收 | 原话为空、日期或链接不合法、错误评分、列数异常或 Excel 公式／错误单元格。源文件仍可在本机追溯。 |

四种状态互斥，总和等于记录总数。缺少来源或许可的内容留在待审暂存区，符合 PDT 正式语料入库前的人工核验要求。结构合格与待审核的记录仍需验证原话、来源、权限与隐私。采样日期与原文日期分别保存，日期精度和缺失信息不会补造。范围自动检查使用明确的日期和产品／品类 ID，研究问题、群体、纳排文本及来源偏好由人工判断。

## 本机保护与复跑

- 项目 ID 和冻结范围 ID 在上传时绑定，确认时在 SQLite 事务内复查。修改范围、切换工作台项目或使用其他项目的上传 ID 均无法改变目标。
- 确认批次使用文件字节摘要、工作表、字段映射、隐私等级与冻结范围构成的幂等指纹。相同配置重试返回原批次的当前收据和撤销状态，即使原文件预览已受限。受限原文件继续遮蔽，含受限行的收据不返回自由文本来源类型汇总。可读取的修订文件或映射可产生新批次，已核验原话在 M05 进行跨批次去重。
- XLSX 以只读方式解析。宏和嵌入文件会被拒收，公式不求值，外部链接不回源。上传会检查文件大小、解压后体积、包内路径和 XML 结构。错误 CSV 防止电子表格解释文本为公式。
- 未确认文件可从首页丢弃。超过 24 小时且未成批的草稿会在下次上传时清理。撤销和丢弃是工作台记录操作，设备备份和 SQLite 日志的保留按本机数据治理政策管理。
- 上传、预览和原文查看限本机同源。原始文件存入本机数据目录。M04 使用 SQLite v3 表，当前工作台通过 v4 增量迁移加入 M05 审核表。

## 本地 API

以下路径均以 `/api/imports` 为前缀。变更及表单请求需要本机同源 `Origin` 与 `X-VOC-Action: connectivity`。

| 方法与路径 | 功能 |
|---|---|
| GET /templates/{csv或xlsx} | 下载仅含表头的模板。 |
| POST /{study_id}/scopes/{scope_id}/uploads | 以 `application/octet-stream` 提交文件，`X-VOC-Filename` 使用百分号编码的文件名。 |
| GET /{study_id}/uploads/{file_id}?sheet_index=0 | 原文件信息、工作表、行数、表头、样本与映射建议。 |
| POST /{study_id}/uploads/{file_id}/preview | 提交工作表索引、字段到列的映射及批次隐私等级，返回质量摘要与确认指纹。 |
| POST /{study_id}/uploads/{file_id}/confirm | 附质量检查返回的 `preview_token` 保存批次。 |
| DELETE /{study_id}/uploads/{file_id} | 丢弃本项目下未成批的上传。 |
| GET /{study_id}/batches | 读取项目批次历史与待导入文件。 |
| GET /{study_id}/batches/{batch_id} | 查看已保存批次和行级状态，支持分页。 |
| GET /{study_id}/batches/{batch_id}/errors.csv | 下载不含原话的错误定位报告。 |
| POST /{study_id}/batches/{batch_id}/revoke | 可审计地撤销批次的后续使用。 |

## M05 原始语料审核

1. 打开「原始语料」，选择项目、导入批次和待核验原话。详情记录项目、冻结范围版本与时间窗、来源地址与发表时间、采样时间、文件指纹、工作表和物理行号。
2. 选择用户原话、背景证据、本机内部材料或合成样本。对照来源和范围，在核验依据中记录访问及保留条件，填写处理原因和 UTC 保留截止日期。核验记录可回查，已通过的原话保存 SHA-256 摘要。来源地址以纯文本展示。
3. 重复组只包含同一项目内有效的已核验公开用户原话。长原话按 Unicode NFC 和空白规范化后的完整文本精确比对，少于 24 字符的原话还要求相同 URL 和外部记录 ID。所显示组和主记录会随排除、到期及撤销重新计算。重复行数只反映记录。
4. 排除、到期、来源资格受限及已审核后撤销的记录在工作台遮蔽原话、来源单元格和审核自由文本。同项目内文件摘要、工作表及行号一致的副本继承限制，含受限行的工作表停止预览。排除审核沿用或缩短已有留存期限，既有空截止日期按审核历史计算。结构化审计、稳定引用和无原话的错误报告仍可回查。原文件和行数据存于本机 SQLite，按来源政策进行物理清理和登记删除审计属于 SOURCE-POLICY 待验范围。

`import_candidates` 是本机暂存审核入口，`research_eligible=0`、`outbound_allowed=0`。稳定 `record_id` 关联 `batch_id`、`study_id` 和冻结的 `scope_id`。原文随 `file_id`、`sheet_name`、`line_number` 定位，审核和快照保存于同一 SQLite。后续品类关系依据证据建立，G-1 决定正式 P0 准入。

本机路由前缀为 `/api/corpus`。GET `/{study_id}/batches` 和 `/{study_id}/batches/{batch_id}` 支持分页，GET `/{study_id}/records/{record_id}` 返回追溯详情，POST `/{study_id}/records/{record_id}/review` 保存核验历史。写操作继续使用本机同源限制。

来源许可撤回通过排除审核登记，处置原因填写「来源许可已撤销」。原记录及同项目内文件摘要、工作表和行号相同的副本随审核历史受限。若另获独立授权，使用能够核对新授权的独立来源另建导入记录。仍在保留期内的记录如需延长留存，核验依据须记录可追溯的新许可。后续入口读取当前状态与有效保留期限，并同时核对来源依据、隐私、内容角色和冻结范围。待审凭本机审核工作台处理，当前 API 的正式研究和外发字段始终为 `false`。[下游契约](../HANDOVER.md#m05--m06-数据契约)
